## 2026-08-05 — hybrid 선정 우선순위 변경 (사용자 결정)
표 수 → 성적 → 점수 순으로 슬롯을 채운다(그전엔 점수 우선).
- 표 = 매칭 live selector 수 + legacy 점수 top-N 1표(점수도 rule 하나로 취급해 특권 제거).
- 근거: 표 수는 신호다 — 실측 0표 승률 48.6%·일등가중 +0.447% → 3표 66.7%·+1.122%.
- **중복 셈이 아니다**: 2표 이상 161건 중 핵심 피처 컬럼(공통 필터 `change_pct` 제외)을 공유하는
  쌍이 낀 경우 0건(외인 서지 3종은 같은 `days_since_frgn_surge` 를 보지만 조건이 배타적).
- ⚠️ **성과 개선 목적이 아니다**: 반사실(7/7~8/4 20거래일·`exec_leg_ret`·비용차감) 이전 +0.771%/일
  (t 1.25) vs 새 규칙 +0.706%(t 1.05) 로 사실상 동률. 목적은 점수 의존을 걷어내고 `rules` 모드로
  가는 중간 단계다. 매칭 종목이 이미 슬롯의 2배(하루 21종 vs 10칸)라 바뀌는 건 내부 순서뿐이다.
- ⚠️ 사후 stats 로 재면 +0.985% 로 보이지만 lookahead 다(그날 시점 성적으로 재야 한다).
- ⚠️ 향후 **같은 피처에 문턱만 다른 rule** 을 등록하면 한 축이 2표를 만든다.
- 남은 숙제: 매칭이 슬롯을 넘칠 때 hybrid 는 엣지 없는 **점수순**으로 자른다.

점수 최하위 10종이 legacy 보다 +0.556%p 좋았다. 이 사실이 아래 두 결정의 공통 전제다 —
`edge_policy` 의 `experimental` 정책([edge-ledger.md](edge-ledger.md))과 확신도 사이징
([gates-sizing.md](gates-sizing.md)).

### closing-bet-score-no-edge
> 종가베팅 종합점수는 익일 청산 손익을 예측 못 함(역상관) → 사이징 등가중화 + weight_tuner backtest 게이팅

자동매매 목표는 "잃지 않고 꾸준히 조금씩(1%) 벌기". 실거래 데이터(2026-06 live) 진단 결과:

- **비용 장벽**: 매도세+수수료 ≈ 0.145%/라운드트립. GROSS 엣지가 이걸 넘어야 이긴다.
  로직 오류 수정 후(6/24~) NET +0.137%, 손익비 2.82로 전략 자체는 흑자 전환.
- **종합점수(score)가 익일 청산 손익을 예측 못 한다**: Spearman(점수,손익) 전체 −0.209, 24일 이후 −0.457.
  고점수 종목이 오히려 더 잃음(다음날 아침 차익실현 매물). 구성요소(수급·정배열·신고가·테마·대장·프로그램)
  전부 상관 0 또는 음수 → **가중치 튜닝으로는 예측력을 못 만든다**(양의 신호가 없음).
- 원인: 신호는 며칠짜리 모멘텀인데 보유는 하룻밤이라 시간축이 어긋남. 후보 풀이 이미 거래대금상위+
  정배열/신고가+테마로 동질하게 걸러져 잔차 점수는 노이즈.

**적용한 변경(이 대화):**
1. `seed_allocator`(trading + jongalab 프리뷰 미러): 점수비례·상위집중 → **등가중** 배분, 잔여현금은
   최소투입 종목 우선. (선정 컷은 여전히 점수순 TOP_N — 사이징만 등가중)
2. `weight_tuner`: backtest IMPROVES=status 'pending'(승인 대상) / 그 외=status 'archived'
   (비적용 — 과적합이라 적용 안 하되 '튜너 동작 여부' 확인용으로 대시보드 표시). 매 실행 [건강지표]
   (스프레드·점수↔손익 상관) 로깅. `approve` API 는 WORSENS 제안 기본 차단(force=true 로만).
   status VARCHAR(10) 라 'archived' 는 마이그레이션 없이 추가됨.

**재개 신호**: [건강지표]의 점수↔손익 상관이 양수로 돌아서면 점수 예측력 회복 → 튜닝/점수tilt 재검토.

### hybrid-vote-priority-0805
> 2026-08-05 hybrid 선정 우선순위를 '표 수(매칭 rule 수 + legacy top-N 1표)→성적→점수'로 변경 — 성과 중립(rules 모드 이행 준비). family 라벨은 축 중복 측정에 못 쓴다(f5_supply 가 6축 포함), 성적 정렬 백테스트는 lookahead 주의

**목적은 성과가 아니라 점수 의존을 걷어내고 rules 모드로 가는 중간 단계**다.

**실측(7/7~8/4 20거래일, exec_leg_ret·비용 차감, live selector 9종)**
| 배분 규칙 | 일평균 | t |
|---|---|---|

| 이전 hybrid(매칭 유무→점수) | **+0.771%** | 1.25 |
| 새 규칙(표수→성적→점수), 그날 시점 성적 | +0.706% | 1.05 |
| 표수→점수(성적 tie-break 없이) | +0.619% | 0.96 |

**함정 2가지 (다음 분석 때 반복하지 말 것)**
1. **`family` 라벨로 축 중복을 재면 안 된다.** "2표 이상의 65%가 같은 family" 라는 수치로 축 중복을

   서로 다른 축 조합까지 중복으로 세어졌다. **핵심 피처 컬럼**(공통 필터 `change_pct` 제외)으로
   재면 2표 이상 161건 중 컬럼 공유 쌍이 낀 경우는 **0건**이다. 외인 서지 3종(carry/pullback1/
   supply_eagle)은 같은 `days_since_frgn_surge` 를 보지만 조건이 배타적이라 동시 매칭이 불가능하다.
   → 사용자 견해("중요한 지표일수록 룰이 많으니 더 가중돼도 된다")가 현 원장에서는 데이터와 맞다.

**Why:** 슬롯 10개가 진짜 병목이라는 발견(`edge-ledger-promotion-gate-pitfalls` 항목 15)의 후속이고,

**How to apply:** 이 규칙의 성과는 강등 감시가 아니라 **선정 결과 자체**로 추적한다 — live rule
구성이 바뀌면(특히 같은 피처 rule 이 늘면) 표 집계 가정을 다시 재라.

### trading-value-floor-over-market-split
> closing_bet 거래대금 조회는 2026-07-28 양시장 통합(mrkt_tp=000)+연속조회로 전환 — 시장별 분리는 코스닥 중소형 과대 대표

closing_bet `_phase1_screening` 의 거래대금 후보 조회는 2026-07-28 **시장별 분리(001 상위50 + 101 상위50) → 양시장 통합(`mrkt_tp=000`, 1페이지 100행)** 으로 전환했다.

**전환 이유** — 분리 방식은 시장 규모 차이를 무시하고 각 50 슬롯을 배분해 코스닥 중소형을 과대 대표했다:

| | 코스피 | 코스닥 |
|---|---|---|
| 슬롯 대비 개별종목(7/28) | 25건 (ETF가 25슬롯 잠식) | **50건 = 67%** |
| 유니버스 비중(7/10~ 458건) | 68% | **32%** |
| 거래대금 중위 | 3,078억 | 1,650억 |
| 시총 중위 | 39.17조 | 3.86조 |
| 2,000억 미달 비중 | 18% | 63% |

전환 후 실측(7/28 Phase 1): 100행 → 하한 통과 46건 → 후보 45건, **코스피 38 / 코스닥 7(16%)**. 유니버스는 32→45건으로 커지고 코스닥 비중은 32%→16%로 내려갔다.

**핵심 구조 — 실질 컷은 TOP_N 이 아니라 거래대금 하한이다.**
- `TOP_N_BY_VALUE`(DB 100)는 통합 순위의 **행 윈도우 상한**일 뿐이다(시장별 쿼터가 아니다).
- `MIN_TRADING_VALUE`(1,000억)가 실질 컷이고, **시총(ka10001) 조회 전에** 판정한다 — 거래대금은 순위 응답에 이미 있으므로. 이 순서 덕에 하한 미달 종목의 무의미한 개별 조회가 사라졌다(이전엔 43건/일 낭비).
- ka10032 는 `mrkt_tp` 무관하게 **1페이지 100행 고정**이고 연속조회(cont-yn/next-key)를 지원한다(7/28 실측: page2 = 767~323억). **연속조회는 쓰지 않는다** — 7/28 기준 78행에서 하한에 도달하고 101~200행 중 하한 통과가 0건이라 2페이지는 무용했다(처음 2페이지로 넣었다가 되돌림). 대신 마지막 행이 하한 이상이면 경고 로그를 남긴다 — 100행 끝이 784억으로 여유가 22행뿐이라 활황장엔 절단될 수 있다. 경고가 뜨면 `max_pages` 를 올린다(kiwoom `/rank/trading-value` 가 `max_pages` 파라미터를 받는다).
