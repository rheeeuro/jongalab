# docs/history — 판정·변경 이력 보관소

각 도메인 `README.md` 는 **현재 구조와 상태**만 적는다. 백테스트 수치·기각 근거·사고 경위 같은
**이력**은 이 디렉터리에 축별로 모은다.

- README 를 읽는 사람은 "지금 코드가 어떻게 생겼나"를 알고 싶다.
- 이 문서를 읽는 사람은 "왜 그렇게 됐나 / 그때 뭘 시도해서 뭐가 기각됐나"를 알고 싶다.

  그 계획을 실행한 뒤의 판정·수치 변경은 이 디렉터리(특히 `edge-ledger.md`)에 쌓는다.
  → 계획 문서와 현재 게이트 조건이 다르면 **여기와 각 README 가 최신**이다.
- 각 앱 `README.md` — **지금 어떻게 생겼는지**(현재 구조·상태·파라미터 값).

## 쓰는 규칙
- **여기는 중요한 의사결정만 남긴다.** 단순 수치 조정(여백·폰트 크기·색 톤·정렬 상수 같은 UI 값
  변경, 임계값 미세 조정)은 **적지 않는다** — 그건 코드와 각 `README.md` 의 현재 값이면 충분하다.
  기록 대상은 **방향을 정하거나 기각한 판단**이다: 왜 그 안을 버렸나 / 무엇이 백테스트로 기각됐나 /
  어떤 사고가 있었나. 수치는 그 판단의 근거로 딸려 올 때만 쓴다.
- **날짜 + 무엇을 바꿨나 + 근거(수치) + 남은 위험** 순으로 한 항목씩 쌓는다(append-only 성격).
- 코드가 바뀌어 항목 내용이 틀리게 되면 **지우지 않고** 새 항목을 아래에 추가한다
  (그 시점 판단의 근거가 남아야 나중에 "그때 왜 그랬나"를 따질 수 있다).
- 현재 동작·파라미터 값은 여기 적지 않는다 — 그건 각 `README.md` 소관이다.
- 판정에 쓴 스크립트·표본 정의처럼 재현에 필요한 것은 항목 안에 함께 적는다.
