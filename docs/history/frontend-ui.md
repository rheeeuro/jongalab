## 뉴스 탭 (`/news`)

### 2026-08-03 — '뉴스 재료 탭' → 3층 구조 재설계
재설계 이유 3가지:
1. **시간축·원문이 없었다** — 뉴스 탭인데 헤드라인이 한 줄도 없었다. 예전 결정("속보 피드는 의도적으로
   두지 않는다")을 뒤집고 `NewsStream` 을 넣되, 파이어호스 문제는 ① 기사 단위로 접고 ② 시세 기사를
   기본 숨김 ③ 큐레이션 계층 **아래**에 두는 것으로 막았다.
2. **모수가 너무 좁았다** — 재료 목록이 그 날 후보 종목만 다뤘는데, 실측 8/3 기준 뉴스가 붙은 종목
   131개 중 후보와 겹친 건 **7개뿐**이었다(화면에 카드 7장). → 후보 밖은 `NewsBuzzRail` 이 덮고,
   후보인 종목엔 '후보' 배지를 달아 두 목록의 관계를 드러낸다.
3. **묶는 축이 사용자 축이 아니었다** — 지속성 등급 3그룹으로 미리 갈라 놓으면 실측상 절반 이상이
   '판정 보류'로 떨어진다(7/31 36건 중 22건, 7/28 은 18건 **전부**). → 단일 목록 + 필터/정렬/검색으로 교체.

기본 날짜를 '오늘'이 아니라 **가장 최근 리포트일**로 둔 이유는 휴장일·장 시작 전에 화면이 통째로
비지 않게 하기 위해서다.
면책 문구는 예전엔 헤더 4줄 문단이라 모바일 첫 화면을 다 먹었다 → 접이식으로 옮기되 핵심 문구
("매수 신호가 아니고 실매매에 개입하지 않습니다")는 닫힌 상태에서도 보이게 남겼다.

### 홈 '오늘 새로 뜬 재료' — 건수 랭킹 → 자기 기저 대비 배수
건수 랭킹은 사실상 시총 랭킹이라 매일 같은 대형주만 보였다(실측 상단 고정: 하이닉스·현대차·삼성전자).

### 2026-08-06 — 홈 '오늘 새로 뜬 재료' 섹션 제거

### 2026-08-11 — 뉴스량 배수 표기 통일 (`평소의 N배`·`×N` → `newsHeatLabel`)
"화면에서 처음 보고 직관적이지 않다"는 지적에서 출발. 문제는 표기가 셋으로 갈린 것보다
**기저가 없는 종목에 배수를 말한 것**이었다.

| 문제 | 실측·근거 |
|---|---|
| 목적어 없음 | `평소의 5.0배` 는 주가·거래량으로도 읽힌다 |
| 문구 3종 | 홈 `평소의 5.0배` / 랭킹 `×5.0` / 재료 목록 `평소 대비 ×5.0` |
| **배수가 아닌 값을 배수로 표기** | 백엔드 분모 하한 `_SURPRISE_FLOOR=1` 탓에 직전 7일 0건이면 배수=오늘 건수. 2026-08-11 `/api/news/heat` 상위 3건이 전부 이 구간(삼성SDI 20건/기저 0.14, NHN 16건/기저 0.0, KT 16건/기저 0.29) — 정렬이 배수순이라 **가장 먼저 읽히는 줄이 가장 틀렸다** |
| 과잉 정밀 | 하루 건수 비율에 소수점 한 자리(`×3.0`) |

바꾼 것: 강조 `뉴스 N배`(정수 반올림, ≥10 은 `10배+`) + 근거 `뉴스 41건 · 평소 10.0건/일`,
기저 0건은 배수 대신 **`첫 등장`**, 1.5배 미만은 `평소 수준`(회색). 정렬 기준 문구도
`뉴스 많은 순` → `평소보다 뉴스 많은 순`(정렬은 처음부터 배수였는데 라벨만 건수처럼 읽혔다).

**배수는 백엔드 `surprise` 와 같은 식(하한 1)을 유지한다.** 0 < 기저 < 1 구간에서 실제보다
작게 나오지만(삼성SDI 실제 143배 → 표기 `10배+`), 화면이 참값을 쓰면 순위와 라벨이 어긋난다.
과장 방향으로 틀리지 않고 근거 줄에 실제 기저(`평소 0.1건/일`)가 보이므로 그대로 둔다.

### 재료 칩에 손익 색(빨강/파랑)을 쓰지 않는 이유
지속성 라벨은 candidate 표본(관찰 전용·미검증)이다. 미검증 라벨이 매수 신호로 읽히면 "게이트 통과를
'검증됨'으로 오독하는 문제"의 UI 버전이 된다 → 배경은 중립 회색, 방향은 화살표로만, title 에 '미검증'.

### 판정 근거 문장 치환 (`lib/news.humanizeMaterialReason`)
LLM 이 낸 `news_label_reason` 에 내부 판정 항목명이 섞여 사용자 화면에 노출됐다
(`next_milestone=0`, `amount_locked를 null로`). 프롬프트는 2026-07-29 고쳤지만 **이미 저장된 행은
소급 불가**라 화면에서 치환한다. 치환으로 앞말 종성이 바뀌면 조사가 틀어지므로(`수치 확정를`)
목적격·부사격 조사도 함께 교정한다. ⚠️ 판정 항목을 추가하면 이 치환표에도 넣어야 한다.

### 종목 상세 '오늘의 뉴스' — 시세보도 접기
"급등/상한가/특징주" 류가 실측 21%라 재료 기사가 묻혔다 → `details/summary` 로 접는다(서버 컴포넌트

## 정보 구조 (탭)

### 2026-08-09 — 추천 최우선 전면 재설계 (8탭 → 5탭, 화면 병합)
"데이터는 괜찮은데 이용자가 뭘 봐야 할지 모르겠다 · 종목 추천을 최우선 기능으로" 요청.
2026-08-07 원복 기록의 교훈("계층 추가가 아니라 **화면 병합**")을 그대로 적용했다.

**재설계를 정당화한 실측 4가지**

| 문제 | 실측 |
|---|---|
| 홈 대표픽 배지가 **사실과 달랐다** | 2026-08-07 리포트 10종목이 **전부** `rule_names` 보유, `rank_no` = 2·4·7·10·11·17·32·41·46·53 — **1위가 없다**. 그런데 `TodayHero`/`TopPicks` 는 `reports[0]`(셀트리온 rank_no=2, 48.6점)에 "종목 랭킹 1위 + 강력 매수"를 하드코딩했다 |
| 핵심 상품이 홈에 없었다 | 홈은 10종목 중 **1개**만 노출, 나머지 9개는 `/stocks`("종목 둘러보기" — 추천 목록으로 안 읽힘). 게다가 10개짜리 목록에 검색창 + 4종 정렬 |
| 첫 화면을 소프트 지표가 먹었다 | h1 이 "AI가 본 오늘의 시장 흐름은 강세 우세"(콘텐츠 언급 감성). 리포트 기준일은 그 카드 맨 아래 12px 회색 |
| 성적표가 있는데 안 보였다 | `gap-stats` 19영업일 94승 82패(53.4%), 편차 큼(7/21·8/3·8/4 10승0패 ↔ 7/15 0승10패). `exec_leg_ret`(실제 체결 손익률)은 갭이 있는 날 **10/10 전부** 채워져 있었는데 화면 어디에도 요약이 없었다 |

**한 것** — 목적지 8 → 5(`추천 / 성적 / 뉴스 / 시장 / 실험실`). 하단 탭 5칸에 정확히 맞아
**'더보기' 바텀시트를 삭제**했고 모든 화면이 1클릭이다(상하 크롬 118px 유지). 병합 내역:
`/stocks` 인덱스 → 홈(리다이렉트) · `/sectors` → `/market` 섹션(리다이렉트) · `/feed` → `/news` 하단
+ 경로 유지 · `/reports` 인덱스 → `/record`(승격, 누적 성적 패널 추가).
sitemap 색인 대상(`/`·`/market`·`/news`·`/reports/*`·`/reports/*/*`·`/stocks/{ticker}`)은 손대지 않았고,
병합·강등 대상은 전부 sitemap 미포함이라 SEO 영향이 없다.

**표시 순번(1,2,3…)을 카드에서 제거했다.** `displayRank`↔`rank_no` 불일치가 '룰 선정 배지' 항목의
오독 사고 원인이었고, 정렬을 바꾸면 다시 어긋난다. 순위 대신 점수 배지 + **'왜 뽑혔나'(룰 한글
제목 최대 2개)** 를 카드에 직접 넣었다 — 예전엔 "룰 선정 3"이라는 숫자뿐이라 어떤 규칙인지는
상세에 들어가야 알 수 있었다.

**홈에 `?date=` 를 두지 않았다.** 날짜별 화면은 `/reports/{date}` 하나뿐이고(이미 색인 대상),
홈과 **같은 레이아웃**을 쓴다. 같은 데이터를 두 URL·두 모양으로 갖지 않기 위해서다.

**평균 실체결 수익률의 창(window) 함정** — `/record` 첫 구현에서 59거래일 평균 갭 +0.14% 옆에
평균 실체결 +0.71% 이 나란히 찍혔다. 실체결 라벨은 매매 경로 가동 이후에만 있어 실제로는
**2026-07-07~08-06 22거래일 196종목**이 모수였다(갭은 05-15~08-06 59일 518종목). 같은 창처럼
읽히면 성적이 부풀려지므로 API 가 `exec_days`·`exec_from_date`·`exec_to_date` 를 함께 내리고
창이 다르면 화면이 그 구간을 명시한다.

**유지한 것(2026-08-07 회귀 재발 방지)**: 리포트 기준일을 화면 최상단에 · `뉴스` 용어 유지 ·
서브탭 바 없음 · `PageHeader` 공통화 안 함.

### 2026-08-09 (2차) — 홈/리포트 분리 · 시장 탭 2분할 · 타이틀 규칙 (사용자 피드백)
1차 재설계 직후 받은 지적 4가지를 반영했다.

**① 랜딩(홈)과 `/reports/{date}` 가 완전히 같았다.** 1차에서 "같은 데이터를 다른 모양으로
보여주지 않는다"며 두 화면에 `PickHero`+`PickList` 를 그대로 공유시켰는데, 그 결과 랜딩이
아카이브의 복사본이 되어 **랜딩만의 역할이 사라졌다**. 공유는 목록(`PickList`)까지로 줄이고
헤더와 주변 블록을 갈랐다 — 홈: 최근 성적·매크로 경고·시장 요약 3종 / 리포트: 날짜 이동·그날
주도 섹터. 홈에서 `DateStepper` 를 뺀 것도 같은 이유다(날짜를 오가는 건 아카이브의 일).

**② 홈에 시장 맥락이 전혀 없었다.** 1차에서 지수·섹터·언급·콘텐츠 4개 섹션을 통째로 지웠는데
(홈 스크롤 단축이 목적), 추천만 남으니 "오늘 시장이 어땠는지"를 알 수 없었다. 되살리되 예전
형태(큰 카드 섹션)가 아니라 **한 줄 가로 스크롤 압축본 3종**(`home/HomeDigest`)으로 넣었다.
여기에 카드·차트·필터를 붙이면 홈이 다시 종합 대시보드가 되므로 컴포넌트 주석에 상한을 박았다.

**③ 시장 탭이 한 화면에 지수+감성+섹터를 쌓아 모바일 스크롤이 길었다.** `?view=index|sector`
세그먼트로 갈랐다. **탭(목적지)은 5개 그대로**이고 화면 안에서만 나누므로 canonical 도
`/market` 하나다 — 2026-08-07 의 "계층을 얹으면 클릭과 크롬이 함께 는다"에 걸리지 않는다.

**④ 페이지 타이틀이 화면마다 달랐다.** `"오늘의 추천 종목 — 종가랩"` / `"뉴스"` /
`"전략 실험실"` / `"[2026-08-06] 삼성전자 일간 리포트"` 처럼 접미사 유무·구분자가 제각각이었다.
루트 레이아웃에 `title.template = "%s · 종가랩"` 을 두고 각 페이지는 **화면 h1 과 같은 짧은
이름**만 선언하게 통일했다. 온스크린 h1 도 탭 라벨에 맞췄다(`지금 시장은 뭐라고 말할까?` →
`콘텐츠`, `지난 추천은 어땠을까요.` → `추천 성적`).
⚠️ 함정 둘: **루트 `app/page.tsx` 는 자기 layout 의 template 적용 대상이 아니라**(자식 세그먼트만
해당) 접미사가 안 붙는다 → `title: { absolute: ... }` 로 예외 처리. 그리고 `app/admin/layout.tsx`
는 클라이언트 컴포넌트라 metadata 를 export 할 수 없어 서버 레이아웃 + 클라 `AdminShell` 로 쪼갰다.

**시드 배분을 버튼+모달로.** 본문 섹션일 때 세로 공간을 크게 먹어 추천 목록을 밀어냈다.
`PickList` 의 `action` 슬롯(결과 줄 우측)에 붙여 홈·리포트 양쪽에서 자리를 차지하지 않는다.

모바일에서는 가로 스크롤 뒤로 뒷칩이 힌트 없이 잘렸다.

**바꾼 것**: 라벨을 **카드당 한 번**만 두는 `시장`(지수 3) / `주도섹터`(1·2위) 2카드.
칩 5개는 375px 에서 124px×5 + gap = 648px 라 폭의 2배(가로 스크롤)였는데, 카드 2장은 모바일에서
1열로 쌓여 스크롤이 사라진다.

**섹터 카드를 픽과 연결했다** — 상위 2섹터 구성종목 ∩ 오늘 픽의 종목 수(`추천 N종목 포함`).
"이 줄이 아래 추천과 무슨 상관인가"에 답하지 못하는 게 '직관적이지 않다'의 절반이었다.
테마 구성종목 코드는 `005930_AL` 같은 접미사가 붙어 오므로 `_` 앞만 비교한다(`closing_bet`
의 `rc.split("_")[0]` 과 같은 처리). 겹침이 없으면 그 사실을 적는다 — 빈 줄이면 '집계 전'과
구분되지 않는다.

**함께 검토하고 안 택한 안 3개** (같은 지적이 다시 오면 여기서부터 시작한다):
- **얇은 텍스트 브리핑 바 한 줄** — 세로는 가장 아끼지만 스파크라인과 시각적 무게가 사라져
  `/market` 로 가는 입구로 안 읽힌다.
- **지수만 남기고 섹터는 픽 카드 배지로 이관** — 섹터를 가장 행동 가능하게 만드는 안이지만
  픽 카드(4줄 고정)에 배지 줄을 더하면 `HERO_ROW_H` 정렬이 다시 걸린다.
- **상단 섹션 제거 후 `PickHero` 에 흡수** — 추천이 완전한 주인공이 되지만 시장 정보가 각주로 강등.

**같은 턴 2차 — 카드 안쪽을 세로 행 → 가로 열로.** 처음엔 카드 안에 항목을 세로 행으로 쌓고
두 카드를 모바일에서도 좌우 2칸(폭 비율을 `sm` 기준으로 2:3 ↔ 3:2 뒤집기)에 넣었다.
**"카드가 가로로 긴데 세로정렬을 하니까 별로"** 로 기각 — 카드 폭은 남는데 카드만 길어졌고,
좁은 칸을 맞추느라 스파크라인(`sm` 미만)과 지수 값(380px 미만)을 숨겨 정보까지 잃고 있었다.
지금은 **열 하나 = 항목 하나**이고 두 카드가 같은 3줄 리듬을 쓴다(지수 `이름/지수값/등락률`,
섹터 `순위/테마명/등락률+종목수`). 모바일은 카드가 각자 전체 폭이라(1열 스택) 지수 열이
343-24 = 319 / 3 ≈ 106px, 섹터 열이 ≈ 155px 로 숨김 규칙 없이 전부 들어간다.
섹터의 픽 겹침 수는 각주 한 줄이 아니라 **이름 줄 곁말**로 붙였다 — 한쪽 카드에만 줄이 하나 더
생기면 두 카드 높이가 어긋난다.

**상한은 '칩 한 줄' → '카드 2장'으로 다시 적었다.** 8/9 2차의 원칙(높이가 추천을 밀어낸다)은
그대로다. 세로는 계산상 모바일에서 칩 한 줄 ≈78px → 카드 2장 ≈160px 로 늘었다 — 가로 스크롤과 폭 낭비를
없앤 대가다. ⚠️ 이 머신은 브라우저 실측이 안 되므로(위 08-11 항목) 실제 높이·열 넘침은 사용자
화면 확인이 필요하다.

### 2026-08-10 (8차) — 홈 2단 좌우 상단 정렬: 결과 줄을 목록 아래로 + 두 히어로 카드 공통 높이
사용자 지적: "종목추천 2·3·4등 부분과 뉴스언급종목 상단이 안 맞는다."
좌측 추천 목록이 **통짜 한 덩어리로 두 행을 걸쳐** 행 경계를 우측 열과 공유하지 않는 게 원인이다.
1행 높이는 성적 카드가 정하고 좌측 목록은 자기 리듬으로 흐르니 두 상단이 우연히 가까울 뿐이었다.

**먼저 블록을 `PickResultBar`·`PickFeatured`·`PickGrid` 로 쪼개 1행/2행에 나눠 놓는 안을 넣었다가
사용자 요청으로 되돌렸다**(블록 구조는 세션 시작 상태 유지). 대신 같은 결과를 두 조정으로 얻는다.
1. **'이 날 결과' + 시드 배분 줄을 목록 아래로 옮겼다.** 위에 있으면 좌측 첫 카드가 그 높이만큼
   내려가 우측 성적 카드와 시작선이 어긋난다. 읽는 순서로도 마무리 수치가 뒤가 맞다.
2. **1등 픽 카드와 성적 카드에 공통 높이 하한을 줬다**(`lib/ui.HERO_ROW_H`).
   서로 다른 열/행이라 CSS 로 높이를 맞출 수단이 없어, 두 카드의 자연 높이보다 큰 같은 값을
   하한으로 잡아 실제 높이를 일치시켰다(현재 값은 `frontend/README.md` 소관).

**같은 날 (8차-b) — 1등 카드 여백 채우기 시도 전부 기각 → 무변경.**
"1등은 데스크탑에서 여백이 많으니 더 다양한 데이터를 보여줘도 좋겠다"에서 출발해 두 안을 넣었다가
**둘 다 사용자 판단으로 원복**했다.
- **수급 4주체 표**(기관·외국인·개인·프로그램 순매수 + 수급 점수·연속일을 `INSET` 한 줄로):
  "별로야". 숫자 5칸이 카드를 미니 표로 만들어 목록 카드의 성격을 벗어난다.
- **스파크라인 + 글자 확대**: 되돌림 요청. 다만 여기서 **재사용 가능한 함정 하나**를 확인했다 —
  남는 여백을 채우려고 `flex-1` 래퍼에 `Sparkline` 을 넣자 **카드 높이가 통째로 무너졌다**.
  이 컴포넌트는 `viewBox="0 0 100 100"` 이라 높이가 auto 로 풀리면 종횡비 1:1 이 적용돼
  폭(≈900px)만큼 세로로 늘어난다. **확정 크기 박스나 absolute 안에서만** 쓸 것
  (`EdgeRuleCard` = `h-6 w-24`, 지수 칩 = `absolute inset-x-0 bottom-0 h-1/2`).
결과적으로 1등 카드는 8차 상태 그대로다(여백은 정렬을 위한 `HERO_ROW_H` 하한의 결과).
2차의 "픽 카드 스파크라인 철회"는 **전체 카드 적용** 건이라 유효하다 — 선이 10번 반복되면
지수 칩 그래프가 묻힌다는 근거는 1등 한 장에는 해당하지 않는다.
바깥 그리드 세로 간격도 카드 그리드와 같은 `gap-3` 으로 맞춘다(가로만 `lg:gap-x-6`) — 뉴스는
`성적 + 세로 간격` 아래, 좌측 2행은 `1등 카드 + gap-3` 아래에서 시작하기 때문이다.
⚠️ 이 정렬은 **두 카드 높이가 하한 안에 있을 때만** 성립한다. 어느 쪽에 줄을 추가하면 상수를
함께 올려야 한다. 구조로 보장하려면 두 카드가 같은 그리드 행을 공유해야 한다(위에서 되돌린 안).

**색이 두 카드를 잇는다** — `lib/report.SCORE_AXES` 를 게이지 구간과 `WhyPicked` 아이콘이 공유한다.
색은 등락·손익(빨강/파랑)과 겹치지 않고 서로 명도가 갈리는 세 가지로 골랐다

| 콘텐츠만 | 39 | 20% |
| **둘 다 없음** | **69** | **36%** |

즉 본문 열이 `수급 + 차트` 두 장뿐인 날이 가장 흔하고(36%), 그때 레일(점수·매매·결과 1032px)이
본문(448px)보다 580px 길어 **왼쪽 아래가 통째로 비었다**. 실제로 렌더해 확인했다.

**③ 채택: `lg:columns-2` 2열 다단 + 카드별 `break-inside-avoid`.** 열 나눔을 브라우저가 맞추므로
카드가 몇 장이든(5~7장) 두 열 높이가 붙는다. 실측 잔차는 뉴스·콘텐츠 있는 날 290px, 없는 날 200px —
고정 2단의 580px 공백과 달리 '아래가 들쭉날쭉한' 수준이다. 모바일은 1열이라 **DOM 순서가 곧 화면
순서**여서 배치를 바꿔도 모바일 읽는 순서를 잃지 않는다(점수 → 매매 → 결과 → 수급 → 차트 → 재료).
- 다단이라 카드 폭이 608px 로 넓어져 `TradePlan` 3열·갭 결과 2행이 제 폭을 받는다. 좁은 레일(304px)
  안에서 3열이 뭉개지던 문제도 같이 사라졌다(`@container` 로 카드 폭에 맞춰 열 수를 정한다).
- **'왜 뽑혔나' 는 다단 밖 전체 폭 밴드**로 뺐다. 이 화면의 본론이라 모바일·데스크탑 모두 먼저
  읽혀야 하고, 3축을 가로 3열로 눕히면 넓은 화면에서 오른쪽이 비는 문제도 함께 해결된다.

**④ 수급 카드의 빈 131px 은 정보로 채웠다** — 5일 순매수 **합계 막대**(기관·외국인·개인·프로그램).
표의 다섯 줄을 눈으로 더해야 알 수 있던 값이고, 채우고 나니 차트 카드와 높이가 448/448 로 맞았다.
여백을 줄이려 차트를 더 낮추는 대신 값을 넣은 이유는, 차트를 200px 이하로 낮추면 캔들이 안 읽히기 때문이다.

**⑤ 줄글은 헤더에서 '왜 뽑혔나' 카드 안으로 옮겼다.** 헤더 아래 회색 문단 3개는 어디에도 속하지
않은 텍스트 블록으로 보였다. 카드 안 도입 문단으로 넣고 ⓐ 한 줄 길이를 `max-w-[68ch]` 로 묶고
ⓑ 숫자·이름만 굵게(`ui/rich-text.RichText`) 처리했다. 문단 수는 3 → **2** 로 줄였고, 빠진
'다음 거래일 아침 결과' 문장은 **결과 카드 안**으로 옮겼다(그 숫자 옆이 그 문장의 자리다).
그래서 결과 카드는 결과가 없는 날에도 대기 문장을 안고 렌더된다.
문단을 한 열로 두니 이번엔 **카드 오른쪽이 비었다**(줄 길이를 40~50자로 묶은 만큼 그대로 남는다).
사용자 제안대로 **lg+ 에서 3축을 오른쪽 열로** 옮겨 `줄글 | 3축` 2열로 바꿨다 — 줄글을 2열로 흘리는
안보다 낫다(성격이 다른 두 블록이 각자 한 열을 채우고, 신문식 2열 본문이 되지 않는다).
남은 90px 여백(3축 210px vs 줄글 120px)은 **문단 사이로 분산**해 두 열의 아래끝을 맞췄다
(`justify-between`, 홈 카드와 같은 규칙). 이때 문단이 2개면 공백이 한 군데에 104px 몰려 구멍처럼
보여서, 리드를 **한 문단 한 가지 = 3문단**(무슨 종목 / 그 날 수치 / 어떻게 뽑혔나)으로 끊었다 —
문단 간격이 고르게 퍼지고 왼쪽 문단이 오른쪽 3축과 같은 리듬으로 읽힌다. 실측 좌우 224/224px.
사용자 요청으로 전략과 종합 점수도 갈라 **최종 4문단**(무슨 종목 / 그 날 수치 / 어떤 전략이 골랐나 /
종합 점수·수급 등급, 간격 35px × 3)이고, 제목 아래 여백도 8 → 20px 로 넓혔다.
마지막으로 **제목(h2)을 왼쪽 열 안으로** 넣어 3축이 제목과 같은 높이에서 시작하게 했다(사용자 요청).
카드 오른쪽 위가 비지 않고, 왼쪽에 제목 높이만큼 내용이 늘어난 만큼 분산될 공백이 줄어 문단 간격도
35 → 20px 로 함께 좁아졌다(카드 높이 320 → 272px, 좌우 아래끝 동일).
설명 문장 전체(줄글·3축 문구·캡션·각주·아침 결과 문장)에 **`break-keep`** 을 걸었다 — 기본 줄바꿈은
단어를 중간에서 끊는다. 360·390·768·1440px 에서 가로 스크롤 없음을 확인했고, 헤드라인처럼 URL·영문이
섞이는 자리는 `break-words` 를 유지했다.

### 2026-08-19 (3차) — 배치 점검: 다단 → **짝 고정 2열 밴드**, 결과 카드는 매매 카드로 흡수
"데이터가 있을 때와 없을 때 모두 고려해서 배치를 점검해 달라"는 요청으로 **10가지 데이터 조합**
(뉴스·콘텐츠·갭 유무 조합 7종 + 권리락·급등감점·점수순선정)을 1440/1024/390px 에서 실측했다.

**드러난 문제 3가지**
| 문제 | 실측 |
|---|---|
| 다단(`columns-2`) 열끝 차가 날마다 튄다 | 0~**444px** (뉴스+갭 1440px 444 / 뉴스+콘텐츠+갭 1024px 443 / 아무것도없음 1024px 11) |
| 결과 없는 날 `아침 결과` 토막 카드 | 높이 **98~106px** (제목 + 대기 문장뿐) |
| 모바일 가로 스크롤 | 삼성SDI 390px 에서 카드 **408px** > 컨테이너 358px |

세 번째가 진짜 버그였다. 밴드 `<div className="grid gap-4 lg:grid-cols-2">` 에 **`grid-cols-1` 이
없어서** 암묵 트랙이 `max-content` 로 커졌다(단일 auto 트랙은 컨테이너보다 커질 수 있다).
`break-keep` 을 의심했지만 `word-break:normal` 로 바꿔도 408px 그대로여서 배제했고, 부모 대비 폭이
처음 넘치는 요소를 찾아 원인을 특정했다.

**바꾼 것**
- 다단 → **짝이 고정된 2열 밴드 3줄**: `[점수 | 매매·결과]` `[수급 | 차트]` `[뉴스 | 언급]`.
  짝의 높이를 설계로 맞추는 쪽이 브라우저 균형보다 낫다 — 카드 수가 날마다 달라지는 화면에서
  자동 균형은 '어느 날 얼마나 어긋날지'를 통제할 수 없다.
- `아침 결과` → **매매 카드의 `footer` 블록**(구분선 + h3). 전제와 결과가 한 장에서 읽히고
  토막 카드가 사라졌다.
- 짧은 쪽 카드(점수)는 **범례 줄 사이로** 남는 공간을 분산(`justify-between`).
- `TradePlan` 칸 수 기준 `@md`(448) → **`@sm`(384)**: 1024px 에서 카드가 440px 를 받아 3칸이
  세로로 쌓이던 것(카드 +200px, 옆 카드 여백 +286px)을 없앴다. 1024px 페이지 높이 2095 → 1918px.
- 재료 줄은 **하나만 있는 날 전체 폭**(빈 절반 방지), 둘 다 있는 날만 2열.

밴드는 `lg:` 가 아니라 **`md:`(768px)부터** 2열이다 — 태블릿을 1열로 두면 페이지가 2,291~2,966px 로
길어진다(2열 1,749~2,342px, 352px 열에서도 수급 표·차트·3칸 모두 들어간다).

**결과** — 짝별 빈 여백 66~339px → **0~29px**(10조합 × 1440/1024/768 전수), 가로 스크롤 0건
(1440/1024/768/390/360), 가장 흔한 조합(뉴스·콘텐츠 둘 다 없는 36%)의 페이지 높이 1523 → **1417px**.
남은 불균형은 뉴스·콘텐츠가 **둘 다 있는 날(25%) 재료 줄 아래끝 차 92~238px** 하나이고, 페이지
맨 끝이라 그대로 둔다.

### 2026-08-19 (4차) — 종합점수 카드 간격: 남는 공간 분산을 되돌리고 '못 받음' 줄로 채움
3차에서 짝 카드가 길 때 점수 카드의 남는 공간을 **범례 줄 사이로 분산**(`justify-between`)했는데,
사용자가 "간격이 이상하다"고 지적했다. 실측하니 줄 간격이 **42px(1440) · 51~78px(1024) · 148~166px
(768)** 까지 벌어져 세 줄이 따로 떠 보였다. 블록 간격(8·12·12·12px)과 대비돼 더 어긋나 보인다.

- **분산을 되돌렸다**(범례 간격 8px 고정). 홈 카드의 `justify-between` 규칙은 **줄 수가 고정된
  짧은 카드**에서 통하는 것이고, 여기처럼 분산 대상이 3줄뿐이면 슬랙이 그대로 줄 간격이 된다.
- 대신 **축마다 '못 받음' 줄**(점수를 못 받은 항목 이름)을 넣어 카드 높이를 315~334 → 345~380px
  으로 올렸다. 여백 메우기용 장식이 아니라 "이 축이 왜 만점이 아닌가"의 답이고, `ScoreAxis.missed`
  가 이미 계산돼 있는데 화면에 내지 않고 있었다.
- `점수↔매매` 짝만 **`lg:` 부터 2열**로 내렸다 — 768px 에서 열이 352px 면 매매 카드의 3칸이 세로로
  쌓여 334 vs 614px 가 되고, 그 차이가 점수 카드 안 빈 공간으로 남는다. 이 짝만 1열로 두면 768px
  페이지가 1,749 → 1,916px 로 늘지만 빈 칸이 사라진다(스크롤 167px 과 빈 칸 280px 의 교환).
- 남은 짝 차이는 **4~94px** 이고 카드 아래 여백으로 둔다(권리락 안내 문단이 매매 카드를 키우는
  1024px 케이스가 최대값 94px).

**검증은 실제 브라우저 렌더로 했다.** 1440·1024·390px + 다크모드 스크린샷, 카드별 좌표·높이·바닥
여백 실측(playwright). 시스템 라이브러리가 없어 처음엔 못 했는데, 그 상태로 클래스만 보고 고쳤던 게
1차에서 짝 배치의 빈 칸을 못 잡은 원인이다 — **레이아웃 변경은 렌더해서 확인한다.**

## 실험실 화면 (`/lab`)

### 검증 중 / 실전 적용 시각 구분
회색조+진행바(모의) vs 컬러(실전) — "모의 성적 ≠ 실탄"을 시각으로 구분한다.

### 2026-08-04 — 판정 종결 전략을 최하단 접힘 섹션으로 (사용자 요청)
진행도 내림차순 정렬 때문에 **게이지가 꽉 찬 종결 전략이 목록 맨 위**에 올라와 승격 임박처럼 읽혔다.
- 카드는 '심사 중' 대신 판정 결과(판정 탈락·재현 실패)를 찍고 사유를 한 줄로 남긴다.
  status 는 candidate 그대로라 모순되는 '검증 중' 배지를 숨긴다.
- 요약 스트립에도 '판정 종결' 타일을 추가하고 '검증 중'·'검증 통과' 집계에서 제외했다 — 종결 전략이
  게이트를 통과한 채 남아 '검증 통과' 숫자를 부풀리고 있었다.
- `decisionLabel` 의 'experimental 정책이면 숨김' 예외를 제거했다 — 평가기는 정책과 무관하게 판정
  일정을 실행하므로 그 예외가 곧 '종결을 숨기는' 원인이었다.
- 판정 여부는 `lib/edge.isDecided` 단일 소스.

### 측정용(benchmark)을 파이프라인 밖으로
승격 게이트 전면 면제라 `promo_eligible` 이 늘 true → 진행률을 보여주면 투입 대기처럼 오해된다.
상태 배지·진행바·'검증 통과' 배지를 숨기고 별도 섹션·요약 타일로 뺐다(`lib/edge.isMeasurementOnly`).
단 '종료'는 수명 정보라 측정용에도 표시한다.

### 카드 높이 통일
검증 상태 슬롯(상태·진행바·설명 3줄)을 조건부로 넣었더니 '남은 조건'이 있는 카드만 키가 커져 그리드가
들쭉날쭉했다 → 설명이 없으면 공백 한 줄이라도 **항상** 렌더한다.

### 서버가 판정, 화면은 렌더링만
프론트가 `min_sample` 로 진행률을 재추정하다 그 조건이 게이트에서 빠지자 **'진행바는 꽉 찼는데
검증 중'** 불일치가 생겼다 → 조건 판정은 서버만 하고 화면은 `promo_eligible`·`promo_blockers`·
`decision_stage` 를 받아 렌더링만 한다(진행바는 거래일 축적만 표시).

### 2026-08-18 — 상세 우측 성적 패널을 질문별 묶음으로 재설계 (사용자 지적)
강등 게이트가 시장 회귀 alpha 로 바뀌면서(→ [edge-ledger.md](edge-ledger.md)) 지표가 9개→13개로
늘었는데, 평평한 2열 그리드에 `실력 몫(alpha)`·`장 민감도(beta)`·`실력 몫 신뢰도` 를 라벨만 얹어
두니 **"이렇게만 써두면 뭔지 모르잖아"** 가 됐다. 문제는 세 가지였다.
1. **묶음이 없다** — 13개가 한 덩어리라 어떤 값끼리 같이 읽어야 하는지 보이지 않았다.
2. **라벨이 약어에 기댄다** — `alpha`·`beta` 는 이 대화에서 만든 말이지 화면 처음 보는 사람의 말이 아니다.
3. **설명이 멀다** — 값은 위 패널, 설명은 아래 패널이고 순서도 서로 달라 대조가 안 됐다.

→ `lib/edge.STAT_GROUPS` 를 단일 소스로 두고 **게이트가 던지는 질문 그대로** 4묶음으로 갈랐다
(얼마나 벌었나 / 믿을 만한가 / 장 덕분인가·전략 덕분인가 / 남들과 비교하면).
두 패널이 같은 배열을 순회하고 머리글도 공용 `GroupHeading` 이라 순서가 어긋날 수 없다.
`STAT_META` 는 `label`+`short`+`help` 3필드가 되어 **타일 안에서 값 밑에 한 줄 힌트**가 붙는다
— 설명 패널까지 스크롤하지 않아도 뜻이 통한다.
라벨은 약어를 버리고 뜻으로 바꿨다: `실력 몫(alpha)`→`장 덕 뺀 수익`(short "알파 · 강등 판단 기준"),
`장 민감도(beta)`→`장 따라가는 정도`(short "1이면 장과 똑같이"), `실력 몫 신뢰도`→`위 수치 믿을 점수`,
`날짜별 신뢰도`→`우연 아닐 점수`, `초과 수익(참고)`→`남들보다 번 몫`.
영문 용어는 라벨에서 빼되 `short`·`help` 에 남겨 알림 문구(`판정값 alpha`)와 대조할 수 있게 했다.
- `최악 하락`은 각주 한 줄에 묻혀 있던 걸 '얼마나 벌었나' 타일로 올렸다 — 손절 정책과 비교하는 값이라
  각주로 두기엔 중요하다.
- 참고 계열(초과 3종)은 숨기지 않고 **`참고` 배지 + 옅은 배경**으로 남겼다. 판정에 안 쓰지만
  "장 덕에 오른 건 아닌가"를 눈으로 확인하는 게 2026-08-04 이후 남은 방어선이라 접으면 안 된다.
- `장 따라가는 정도`(beta)에는 손익 색을 주지 않는다 — 수익률이 아니라 성질이라 1.5 가 '좋다'는
  뜻이 아니다(미검증 라벨에 손익 색을 쓰지 않는 기존 규칙과 같은 이유).
