## 뉴스 탭 (`/news`)

### 2026-08-03 — '뉴스 재료 탭' → 3층 구조 재설계
재설계 이유 3가지:
1. **시간축·원문이 없었다** — 뉴스 탭인데 헤드라인이 한 줄도 없었다. 예전 결정("속보 피드는 의도적으로
   두지 않는다")을 뒤집고 `NewsStream` 을 넣되, 파이어호스 문제는 ① 기사 단위로 접고 ② 시세 기사를
   기본 숨김 ③ 큐레이션 계층 **아래**에 두는 것으로 막았다.
2. **모수가 너무 좁았다** — 재료 목록이 그 날 후보 종목만 다뤘는데, 실측 8/3 기준 뉴스가 붙은 종목
   131개 중 후보와 겹친 건 **7개뿐**이었다(화면에 카드 7장). → 후보 밖은 `NewsBuzzRail` 이 덮고,
   후보인 종목엔 '후보' 배지를 달아 두 목록의 관계를 드러낸다.
3. **묶는 축이 사용자 축이 아니었다** — 지속성 등급 3그룹으로 미리 갈라 놓으면 실측상 절반 이상이
   '판정 보류'로 떨어진다(7/31 36건 중 22건, 7/28 은 18건 **전부**). → 단일 목록 + 필터/정렬/검색으로 교체.

기본 날짜를 '오늘'이 아니라 **가장 최근 리포트일**로 둔 이유는 휴장일·장 시작 전에 화면이 통째로
비지 않게 하기 위해서다.
면책 문구는 예전엔 헤더 4줄 문단이라 모바일 첫 화면을 다 먹었다 → 접이식으로 옮기되 핵심 문구
("매수 신호가 아니고 실매매에 개입하지 않습니다")는 닫힌 상태에서도 보이게 남겼다.

### 홈 '오늘 새로 뜬 재료' — 건수 랭킹 → 자기 기저 대비 배수
건수 랭킹은 사실상 시총 랭킹이라 매일 같은 대형주만 보였다(실측 상단 고정: 하이닉스·현대차·삼성전자).

### 재료 칩에 손익 색(빨강/파랑)을 쓰지 않는 이유
지속성 라벨은 candidate 표본(관찰 전용·미검증)이다. 미검증 라벨이 매수 신호로 읽히면 "게이트 통과를
'검증됨'으로 오독하는 문제"의 UI 버전이 된다 → 배경은 중립 회색, 방향은 화살표로만, title 에 '미검증'.

### 판정 근거 문장 치환 (`lib/news.humanizeMaterialReason`)
LLM 이 낸 `news_label_reason` 에 내부 판정 항목명이 섞여 사용자 화면에 노출됐다
(`next_milestone=0`, `amount_locked를 null로`). 프롬프트는 2026-07-29 고쳤지만 **이미 저장된 행은
소급 불가**라 화면에서 치환한다. 치환으로 앞말 종성이 바뀌면 조사가 틀어지므로(`수치 확정를`)
목적격·부사격 조사도 함께 교정한다. ⚠️ 판정 항목을 추가하면 이 치환표에도 넣어야 한다.

### 종목 상세 '오늘의 뉴스' — 시세보도 접기
"급등/상한가/특징주" 류가 실측 21%라 재료 기사가 묻혔다 → `details/summary` 로 접는다(서버 컴포넌트
유지, CSS-only 토글).

## '룰 선정' 배지 (2026-07-29)

hybrid 모드는 점수 순위와 무관하게 종목을 뽑는데 목록은 표시 순번(1,2,3…)을 매기므로, 배지 없이는
점수로 뽑힌 것처럼 읽혔다 — **실측 점수 62위가 화면에서 "10위"로 표시**됐다.
→ 배지 + 부제에 `점수 N위` 병기. 카드 배지는 카드 전체가 이미 `Link` 라 링크 불가해서 룰로 가는 링크는
리포트 상세에만 둔다. 상세 칩은 **한글 제목**(`edge_rule.title`)을 쓰고 코드 슬러그는 링크 경로로만
남긴다(사용자 화면에 내부 식별자를 노출하지 않는다는 `/lab` 용어 원칙).

## 실험실 화면 (`/lab`)

### 검증 중 / 실전 적용 시각 구분
회색조+진행바(모의) vs 컬러(실전) — "모의 성적 ≠ 실탄"을 시각으로 구분한다.

### 2026-08-04 — 판정 종결 전략을 최하단 접힘 섹션으로 (사용자 요청)
진행도 내림차순 정렬 때문에 **게이지가 꽉 찬 종결 전략이 목록 맨 위**에 올라와 승격 임박처럼 읽혔다.
- 카드는 '심사 중' 대신 판정 결과(판정 탈락·재현 실패)를 찍고 사유를 한 줄로 남긴다.
  status 는 candidate 그대로라 모순되는 '검증 중' 배지를 숨긴다.
- 요약 스트립에도 '판정 종결' 타일을 추가하고 '검증 중'·'검증 통과' 집계에서 제외했다 — 종결 전략이
  게이트를 통과한 채 남아 '검증 통과' 숫자를 부풀리고 있었다.
- `decisionLabel` 의 'experimental 정책이면 숨김' 예외를 제거했다 — 평가기는 정책과 무관하게 판정
  일정을 실행하므로 그 예외가 곧 '종결을 숨기는' 원인이었다.
- 판정 여부는 `lib/edge.isDecided` 단일 소스.

### 측정용(benchmark)을 파이프라인 밖으로
승격 게이트 전면 면제라 `promo_eligible` 이 늘 true → 진행률을 보여주면 투입 대기처럼 오해된다.
상태 배지·진행바·'검증 통과' 배지를 숨기고 별도 섹션·요약 타일로 뺐다(`lib/edge.isMeasurementOnly`).
단 '종료'는 수명 정보라 측정용에도 표시한다.

### 카드 높이 통일
검증 상태 슬롯(상태·진행바·설명 3줄)을 조건부로 넣었더니 '남은 조건'이 있는 카드만 키가 커져 그리드가
들쭉날쭉했다 → 설명이 없으면 공백 한 줄이라도 **항상** 렌더한다.

### 서버가 판정, 화면은 렌더링만
프론트가 `min_sample` 로 진행률을 재추정하다 그 조건이 게이트에서 빠지자 **'진행바는 꽉 찼는데
검증 중'** 불일치가 생겼다 → 조건 판정은 서버만 하고 화면은 `promo_eligible`·`promo_blockers`·
`decision_stage` 를 받아 렌더링만 한다(진행바는 거래일 축적만 표시).
