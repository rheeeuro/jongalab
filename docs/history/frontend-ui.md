## 뉴스 탭 (`/news`)

### 2026-08-03 — '뉴스 재료 탭' → 3층 구조 재설계
재설계 이유 3가지:
1. **시간축·원문이 없었다** — 뉴스 탭인데 헤드라인이 한 줄도 없었다. 예전 결정("속보 피드는 의도적으로
   두지 않는다")을 뒤집고 `NewsStream` 을 넣되, 파이어호스 문제는 ① 기사 단위로 접고 ② 시세 기사를
   기본 숨김 ③ 큐레이션 계층 **아래**에 두는 것으로 막았다.
2. **모수가 너무 좁았다** — 재료 목록이 그 날 후보 종목만 다뤘는데, 실측 8/3 기준 뉴스가 붙은 종목
   131개 중 후보와 겹친 건 **7개뿐**이었다(화면에 카드 7장). → 후보 밖은 `NewsBuzzRail` 이 덮고,
   후보인 종목엔 '후보' 배지를 달아 두 목록의 관계를 드러낸다.
3. **묶는 축이 사용자 축이 아니었다** — 지속성 등급 3그룹으로 미리 갈라 놓으면 실측상 절반 이상이
   '판정 보류'로 떨어진다(7/31 36건 중 22건, 7/28 은 18건 **전부**). → 단일 목록 + 필터/정렬/검색으로 교체.

기본 날짜를 '오늘'이 아니라 **가장 최근 리포트일**로 둔 이유는 휴장일·장 시작 전에 화면이 통째로
비지 않게 하기 위해서다.
면책 문구는 예전엔 헤더 4줄 문단이라 모바일 첫 화면을 다 먹었다 → 접이식으로 옮기되 핵심 문구
("매수 신호가 아니고 실매매에 개입하지 않습니다")는 닫힌 상태에서도 보이게 남겼다.

### 홈 '오늘 새로 뜬 재료' — 건수 랭킹 → 자기 기저 대비 배수
건수 랭킹은 사실상 시총 랭킹이라 매일 같은 대형주만 보였다(실측 상단 고정: 하이닉스·현대차·삼성전자).

### 2026-08-06 — 홈 '오늘 새로 뜬 재료' 섹션 제거
같은 데이터(`/api/news/heat`)를 `/news` 탭의 `NewsBuzzRail` 이 더 넓은 모수로 이미 보여주고 있어
홈에서는 중복이었다. 홈(오늘 탭)은 추천·수급·언급 흐름으로 짧게 유지한다.
`components/today/NewsHeat.tsx` 삭제 + `app/page.tsx` 의 `getNewsHeat` 페치 제거(홈 SSR 왕복 1회 감소).
API `/api/news/heat` 자체는 `/news` 가 계속 쓰므로 그대로 둔다.

### 재료 칩에 손익 색(빨강/파랑)을 쓰지 않는 이유
지속성 라벨은 candidate 표본(관찰 전용·미검증)이다. 미검증 라벨이 매수 신호로 읽히면 "게이트 통과를
'검증됨'으로 오독하는 문제"의 UI 버전이 된다 → 배경은 중립 회색, 방향은 화살표로만, title 에 '미검증'.

### 판정 근거 문장 치환 (`lib/news.humanizeMaterialReason`)
LLM 이 낸 `news_label_reason` 에 내부 판정 항목명이 섞여 사용자 화면에 노출됐다
(`next_milestone=0`, `amount_locked를 null로`). 프롬프트는 2026-07-29 고쳤지만 **이미 저장된 행은
소급 불가**라 화면에서 치환한다. 치환으로 앞말 종성이 바뀌면 조사가 틀어지므로(`수치 확정를`)
목적격·부사격 조사도 함께 교정한다. ⚠️ 판정 항목을 추가하면 이 치환표에도 넣어야 한다.

### 종목 상세 '오늘의 뉴스' — 시세보도 접기
"급등/상한가/특징주" 류가 실측 21%라 재료 기사가 묻혔다 → `details/summary` 로 접는다(서버 컴포넌트
유지, CSS-only 토글).

## 정보 구조 (탭)

### 2026-08-09 — 추천 최우선 전면 재설계 (8탭 → 5탭, 화면 병합)
"데이터는 괜찮은데 이용자가 뭘 봐야 할지 모르겠다 · 종목 추천을 최우선 기능으로" 요청.
2026-08-07 원복 기록의 교훈("계층 추가가 아니라 **화면 병합**")을 그대로 적용했다.

**재설계를 정당화한 실측 4가지**

| 문제 | 실측 |
|---|---|
| 홈 대표픽 배지가 **사실과 달랐다** | 2026-08-07 리포트 10종목이 **전부** `rule_names` 보유, `rank_no` = 2·4·7·10·11·17·32·41·46·53 — **1위가 없다**. 그런데 `TodayHero`/`TopPicks` 는 `reports[0]`(셀트리온 rank_no=2, 48.6점)에 "종목 랭킹 1위 + 강력 매수"를 하드코딩했다 |
| 핵심 상품이 홈에 없었다 | 홈은 10종목 중 **1개**만 노출, 나머지 9개는 `/stocks`("종목 둘러보기" — 추천 목록으로 안 읽힘). 게다가 10개짜리 목록에 검색창 + 4종 정렬 |
| 첫 화면을 소프트 지표가 먹었다 | h1 이 "AI가 본 오늘의 시장 흐름은 강세 우세"(콘텐츠 언급 감성). 리포트 기준일은 그 카드 맨 아래 12px 회색 |
| 성적표가 있는데 안 보였다 | `gap-stats` 19영업일 94승 82패(53.4%), 편차 큼(7/21·8/3·8/4 10승0패 ↔ 7/15 0승10패). `exec_leg_ret`(실제 체결 손익률)은 갭이 있는 날 **10/10 전부** 채워져 있었는데 화면 어디에도 요약이 없었다 |

**한 것** — 목적지 8 → 5(`추천 / 성적 / 뉴스 / 시장 / 실험실`). 하단 탭 5칸에 정확히 맞아
**'더보기' 바텀시트를 삭제**했고 모든 화면이 1클릭이다(상하 크롬 118px 유지). 병합 내역:
`/stocks` 인덱스 → 홈(리다이렉트) · `/sectors` → `/market` 섹션(리다이렉트) · `/feed` → `/news` 하단
+ 경로 유지 · `/reports` 인덱스 → `/record`(승격, 누적 성적 패널 추가).
sitemap 색인 대상(`/`·`/market`·`/news`·`/reports/*`·`/reports/*/*`·`/stocks/{ticker}`)은 손대지 않았고,
병합·강등 대상은 전부 sitemap 미포함이라 SEO 영향이 없다.

**표시 순번(1,2,3…)을 카드에서 제거했다.** `displayRank`↔`rank_no` 불일치가 '룰 선정 배지' 항목의
오독 사고 원인이었고, 정렬을 바꾸면 다시 어긋난다. 순위 대신 점수 배지 + **'왜 뽑혔나'(룰 한글
제목 최대 2개)** 를 카드에 직접 넣었다 — 예전엔 "룰 선정 3"이라는 숫자뿐이라 어떤 규칙인지는
상세에 들어가야 알 수 있었다.

**홈에 `?date=` 를 두지 않았다.** 날짜별 화면은 `/reports/{date}` 하나뿐이고(이미 색인 대상),
홈과 **같은 레이아웃**을 쓴다. 같은 데이터를 두 URL·두 모양으로 갖지 않기 위해서다.

**평균 실체결 수익률의 창(window) 함정** — `/record` 첫 구현에서 59거래일 평균 갭 +0.14% 옆에
평균 실체결 +0.71% 이 나란히 찍혔다. 실체결 라벨은 매매 경로 가동 이후에만 있어 실제로는
**2026-07-07~08-06 22거래일 196종목**이 모수였다(갭은 05-15~08-06 59일 518종목). 같은 창처럼
읽히면 성적이 부풀려지므로 API 가 `exec_days`·`exec_from_date`·`exec_to_date` 를 함께 내리고
창이 다르면 화면이 그 구간을 명시한다.

**유지한 것(2026-08-07 회귀 재발 방지)**: 리포트 기준일을 화면 최상단에 · `뉴스` 용어 유지 ·
서브탭 바 없음 · `PageHeader` 공통화 안 함.

### 2026-08-09 (2차) — 홈/리포트 분리 · 시장 탭 2분할 · 타이틀 규칙 (사용자 피드백)
1차 재설계 직후 받은 지적 4가지를 반영했다.

**① 랜딩(홈)과 `/reports/{date}` 가 완전히 같았다.** 1차에서 "같은 데이터를 다른 모양으로
보여주지 않는다"며 두 화면에 `PickHero`+`PickList` 를 그대로 공유시켰는데, 그 결과 랜딩이
아카이브의 복사본이 되어 **랜딩만의 역할이 사라졌다**. 공유는 목록(`PickList`)까지로 줄이고
헤더와 주변 블록을 갈랐다 — 홈: 최근 성적·매크로 경고·시장 요약 3종 / 리포트: 날짜 이동·그날
주도 섹터. 홈에서 `DateStepper` 를 뺀 것도 같은 이유다(날짜를 오가는 건 아카이브의 일).

**② 홈에 시장 맥락이 전혀 없었다.** 1차에서 지수·섹터·언급·콘텐츠 4개 섹션을 통째로 지웠는데
(홈 스크롤 단축이 목적), 추천만 남으니 "오늘 시장이 어땠는지"를 알 수 없었다. 되살리되 예전
형태(큰 카드 섹션)가 아니라 **한 줄 가로 스크롤 압축본 3종**(`home/HomeDigest`)으로 넣었다.
여기에 카드·차트·필터를 붙이면 홈이 다시 종합 대시보드가 되므로 컴포넌트 주석에 상한을 박았다.

**③ 시장 탭이 한 화면에 지수+감성+섹터를 쌓아 모바일 스크롤이 길었다.** `?view=index|sector`
세그먼트로 갈랐다. **탭(목적지)은 5개 그대로**이고 화면 안에서만 나누므로 canonical 도
`/market` 하나다 — 2026-08-07 의 "계층을 얹으면 클릭과 크롬이 함께 는다"에 걸리지 않는다.

**④ 페이지 타이틀이 화면마다 달랐다.** `"오늘의 추천 종목 — 종가랩"` / `"뉴스"` /
`"전략 실험실"` / `"[2026-08-06] 삼성전자 일간 리포트"` 처럼 접미사 유무·구분자가 제각각이었다.
루트 레이아웃에 `title.template = "%s · 종가랩"` 을 두고 각 페이지는 **화면 h1 과 같은 짧은
이름**만 선언하게 통일했다. 온스크린 h1 도 탭 라벨에 맞췄다(`지금 시장은 뭐라고 말할까?` →
`콘텐츠`, `지난 추천은 어땠을까요.` → `추천 성적`).
⚠️ 함정 둘: **루트 `app/page.tsx` 는 자기 layout 의 template 적용 대상이 아니라**(자식 세그먼트만
해당) 접미사가 안 붙는다 → `title: { absolute: ... }` 로 예외 처리. 그리고 `app/admin/layout.tsx`
는 클라이언트 컴포넌트라 metadata 를 export 할 수 없어 서버 레이아웃 + 클라 `AdminShell` 로 쪼갰다.

**시드 배분을 버튼+모달로.** 본문 섹션일 때 세로 공간을 크게 먹어 추천 목록을 밀어냈다.
`PickList` 의 `action` 슬롯(결과 줄 우측)에 붙여 홈·리포트 양쪽에서 자리를 차지하지 않는다.

### 2026-08-10 — 홈을 대시보드형으로 (지표를 픽 **위**로, 데스크탑 2단)
"종목 추천이 메인은 맞지만 종목만 10개 있는 느낌이고, 기타 지표는 아래로 스크롤해야 보인다.
대시보드처럼 한눈에 들어왔으면" 요청.

**원인은 8/9 2차 결정의 부작용이었다.** 그때 시장 요약을 되살리면서 "추천을 밀어내지 않게"
하려고 `HomeDigest` 3종을 **픽 카드 10장 아래**에 뒀다. 그 결과 지표가 사실상 안 보였다.
세로 스택 순서가 `헤더(h1 3xl + 부제 + 면책) → 성적 → 매크로 → 픽 10장 → 지수 → 섹터 → 뉴스`
였고, 픽 카드 자체도 근거 박스·배지 줄·점수 줄·갭 박스가 각각 별도 블록이라 카드 한 장이
컸다(모바일 1열에서 한 화면에 2장 남짓).

**한 것 3가지 — 목적은 "지표를 위로 올리되 추천이 첫 화면을 지키게" 다.**

| 축 | 전 | 후 |
|---|---|---|
| 지표 위치 | 픽 10장 **아래**, 섹션 3개(각 한 줄 가로 스크롤) | 픽 **위**, 칩 한 줄(`home/MarketPulse`) — 지수 3 + 주도섹터 2 |
| 픽 카드 | 5블록(헤더·근거 박스·배지/점수 줄·갭 박스) | 4줄 고정(헤더·서브·`근거+점수`·`배지+갭`) — 세로 길이 약 절반 |
| 레이아웃 | 1단 세로 스택 | lg+ 2단(좌 픽 / 우 성적·뉴스), 모바일은 `성적 → 픽 → 뉴스` |

- **`IndexDigest`/`SectorDigest` 는 칩으로 흡수**하고 `HomeDigest.tsx` 를 삭제했다. 지수는 국내 2
  (코스피·코스닥) + 미국 1(S&P 500) 로 잘랐다 — 앞에서 3개를 자르면 `KR[2]` 가 원/달러 환율이라
  '지수 줄'로 읽히지 않았다. 나머지(환율·필라델피아 반도체 등)는 `/market` 에 남는다.
- **`NewsDigest` 는 가로 칩 → 세로 목록 5건**으로 바꿨다. 데스크탑에서 19rem 사이드바에 들어가야
  하는데 `sm:grid-cols-3 lg:grid-cols-5` 짜리 가로 칩은 좁은 열에서 읽히지 않는다.
- **모바일 순서를 지키려고 명시적 그리드 좌표를 썼다.** 사이드바를 통째로 한 `<div>` 로 묶어
  `lg:order` 로 밀면 모바일에서 성적·뉴스가 **둘 다** 픽 위로 올라가 픽이 다시 밀린다.
  자식 3개를 `lg:col-start`/`lg:row-start` 로 배치해 DOM 순서(성적 → 픽 → 뉴스)를 그대로 뒀다.
- **`PickList` 의 열 수는 컨테이너 쿼리**(`@container` + `@md:`/`@4xl:`)로 바꿨다. 홈은 사이드바에
  폭을 내주고 `/reports/{date}` 는 전체 폭을 쓰는데, 화면 폭 기준(`lg:grid-cols-3`)이면 홈의 좌측
  열이 lg 에서 3열이 되어 카드 하나가 ~216px 로 찌그러진다.

**8/9 2차의 상한("홈이 다시 종합 대시보드가 되면 추천이 묻힌다")은 유지한다.** 그 상한을
'지표는 아래에' 가 아니라 **'지표는 칩 한 줄까지'** 로 다시 적었다 — 위치가 아니라 높이가
추천을 밀어내는 실제 원인이었다. 컴포넌트 주석과 README 에 이 상한을 박아 뒀다.

### 2026-08-10 (2차) — 홈 시각 언어 개편 (표면 3단계 · 지수 스파크라인 · 색 역할 고정)
같은 날 구조를 바꾼 뒤 받은 지적: "느낌은 괜찮은데 **카드가 다 똑같이 흰색이라 구분도 안 되고**,
시장 탭처럼 지수에 그래프가 있는 것도 아니다."

**원인 ①: 흰 카드가 배경과 같았다.** 페이지 배경은 `#F9FAFB`(dark `#0F0F12`)인데 카드는
`bg-white`(dark `bg-slate-900/60`)뿐이라 경계선이 없었다. 색으로 층을 나눌 여지가 거의 없는
값이라 **경계는 배경색이 아니라 헤어라인 링이 만들게** 바꿨다 — `lib/ui.ts` 의 `CARD`
(`ring-1 ring-slate-200/70 + shadow-sm`, dark `ring-white/5`) · `INSET` · `PANEL` 3단계.

**원인 ②: 블록이 전부 같은 모양이었다.** 역할이 다른데 생김새가 같으면 위계가 안 읽힌다.
- 지수 칩 → 시장 탭과 같은 언어로 통일(바닥 `Sparkline` + 추세 아이콘). 데이터는 이미
  `/api/market-indices` 가 `sparkline`(코스피·코스닥 15p, S&P 80p)을 주고 있었는데 홈만 안 썼다.

  모수가 안 읽혔다. (처음엔 어두운 패널로 띄웠다가 같은 날 철회 — 바로 아래 항목)
- 뉴스 요약 → 배수(`surprise`) 가로 막대.

**색 역할을 고정하고 실측으로 하나 기각했다.** 등락·손익 = 빨강/파랑, 크기 = 호박색,
앱 강조 = 남색. 처음엔 뉴스 막대를 앱 강조색(indigo-600)으로 뒀는데, 팔레트 검증에서
**indigo #4f46e5 ↔ blue #2563eb 가 ΔE 2.8(deutan) · 6.7(정상 시야)** 로 사실상 같은 색이었다.
사이드바에서 성적 패널의 파란 '패' 구간 바로 아래에 남색 막대가 놓이는 배치라 '하락'으로
오독될 수 있어 **호박색(#f59e0b, 최근접 쌍 ΔE 14.5 deutan / 21.6 정상)** 으로 바꿨다.
violet(#8b5cf6)도 같은 이유로 기각(ΔE 1.3 deutan). 방향 2색(rose-600/blue-600)은 전 항목 통과,
어두운 패널 위에서는 400 스텝이 명도 밴드를 벗어나 **rose-500/blue-500** 으로 내렸다.
재현: `dataviz` 스킬의 `scripts/validate_palette.js "<hex,…>" --mode light --surface "#F9FAFB"`.

**픽 카드 스파크라인은 시도했다가 철회했다(사용자 판단: "과하다").** `daily_stock_report` 응답이
종목당 `hourly_candles` 1,737개(응답 1.9MB)를 이미 싣고 있어 백엔드 변경 없이 카드마다
최근 흐름 선을 깔 수 있었지만, 카드 10장에 선이 반복되면 정작 지수 칩의 그래프가 묻힌다.
**그래프는 지수·섹터 줄에만 둔다.**

**좌측 등급 띠의 한계도 기록해 둔다.** 픽 카드 왼쪽 세로 띠를 수급 등급 색으로 넣었는데,
등급 분포가 D 로 크게 치우쳐 있다(2026-08-10 은 **10종목 전부 D**, 08-07 A1·C3·D6,
08-05 A1·B4·D5, 08-03 D8·C2). 전 종목 D 인 날은 옅은 회색 한 줄로만 보인다 — 등급이 없는 날
색으로 강조하지 않는 게 맞다고 보고 유지했다. 카드 구분의 1차 단서는 등락률 색면 pill 이다.

### 2026-08-11 — 1등 카드 여백: 글자 확대 + 선정 근거 블록 (장중 차트·좌우 2단은 기각)
사용자 지적: "1등 종목이 높이가 높아지면서 아래가 비었다 — 데스크탑 너비에서는 폰트를 좀 키워주면
될 것 같다." 8차-b 에서 기각된 두 안(수급 4주체 표 · 스파크라인)은 **데이터를 더 넣는** 방향이었고,

걸리지 않는다.

**확인한 것 (2026-08-11 홈)** — 정렬 규칙 자체는 정상이었다. 그날 선정은 2종목뿐이고 둘 다
`f5_frgn_surge_flat34` 1개라 `규칙 수 → rank_no` 대로 삼성전자(rank 1, 16.6점) → SK하이닉스
(rank 2, 12.9점)다. 여백의 원인은 순서가 아니라 `HERO_ROW_H`(224px) 하한과 1등 카드 자연 높이

상단 정렬은 그대로다. 모바일은 하한이 `lg:` 한정이라 여백이 없어 원래 크기를 유지한다.

"1등은 3열을 차지하니 스파크라인을 넣고 데스크탑은 별개 레이아웃으로" 요청으로 시작해
1등 카드를 `lg:flex-row`(좌 정보 열 / 우 차트 패널)로 짜고 축을 일봉 60거래일 → **당일 5분봉**

원복"** 요청으로 코드·문서·마이그레이션을 전부 되돌렸다. 8차-b 에 이어 **1등 카드에 시각 요소를

되돌렸어도 **다시 조사할 필요가 없는 사실**만 남긴다.

  수밖에 없고, 파싱은 `core/daily_ohlc.build_minute_price_by_time` 이 이미 갖고 있다.

  (07-01 도 78봉 확인). 1분봉은 같은 비용이지만 카드 폭 ≈350px 에 390점이면 선이 뭉개진다.

  `absolute inset-0` 로 막아야 한다(높이를 svg 가 아니라 박스가 정한다). 8차-b 에서 카드가
  무너진 원인이 이거였고, 이 방식으로는 실제로 무너지지 않았다.
- **시장 탭 지수 칩 스파크라인도 당일 5분봉**이다(`market_data._fetch_sparkline`,
  yfinance `1d/5m`, 최근 80점, 빈 심볼은 일봉 1개월 폴백). 코스피200 선물 두 칩만 KIS 당일 1분봉.
- 남은 흔적 없음. 운영 DB 의 `daily_stock_report.min5_candles` 컬럼(2026-08-11 10:00 회차가 선정
  10종목에 13봉씩 쓴 값)도 같은 날 `DROP COLUMN` 으로 되돌렸다 — 코드·스키마 파일·DB 가 다시 일치한다.

**3차 — 데스크탑 1등 카드에 '선정 근거' 블록(채택). 좌우 2단은 그 과정에서 기각.**
"여백을 채우는 방식으로 처음부터 다시 디자인" 요청. 앞선 기각들의 공통점은 **카드에 없던
축(수급 숫자·가격 시계열)을 새로 들여온 것**이었다 → 이번엔 카드가 이미 말하던 것("규칙이
뽑았다")을 **펼치는** 방향으로 갔다. 목록의 작은 카드는 룰 제목 2개를 한 줄로 줄여 쓰는데
(`reasonText`), 1등 카드는 같은 내용을 제목 + **초심자용 설명** + 상태까지 편다. 새 조회·컬럼 없음.
- 처음엔 좌우 2단(`lg:flex-row`, 우측 44% 열)으로 냈다가 **"열로 나뉘어지니까 별로"** 로 기각.
  → **한 열 유지 + 카드 전체 폭을 쓰는 `INSET` 근거 블록**을 이름 줄 아래에 붙이는 형태로 확정.
  1등 카드에 세로 분할선을 넣는 안은 이걸로 닫힌다.

  읽는다" 사고와 같은 형태다. 상태 라벨도 자체 문구를 만들지 않고 스코어보드와 같은

### 2026-08-10 (8차) — 홈 2단 좌우 상단 정렬: 결과 줄을 목록 아래로 + 두 히어로 카드 공통 높이

세그먼트 컨트롤은 두 화면이 쓰게 되어 `components/ViewSegment` 로 뽑았다. **이것은
2026-08-07 에 기각된 '전역 2단 서브탭 바'와 다르다** — 레이아웃이 아니라 화면 본문 안에 있고,
목적지(탭)를 늘리지 않으며(5개 고정), 쿼리라 canonical 도 원래 경로 하나로 남는다.
모바일 상하 크롬 118px 도 그대로다.

### 2026-08-07 — 4탭 + 2단 서브탭 재편 시도 → **전면 원복(기각)**
수평 8탭(`오늘·실험실·시장·종목·섹터·뉴스·콘텐츠·리포트`)이 "어디를 봐야 하는지 모르겠다"는 문제로
① 질문 기준 4탭(`오늘/종목/재료/실험실`) ② 레이아웃 전역 2단 서브탭 바 ③ 화면 헤더 공통화
(`PageHeader`)를 만들어 봤다. **UX 가 오히려 나빠져 코드는 전부 원복**했다. 측정된 회귀 4가지:

| 회귀 | 실측 |
|---|---|
| 클릭 증가 | 목적지 8개가 그대로 8개인데 계층만 늘어 **시장·섹터·리포트·콘텐츠가 1→2클릭** |
| 모바일 크롬 | 상하 고정 영역 **118px → 167px**(375×667 기준 18%→25%). 게다가 모바일 상단 Navbar 57px 는 탭이 `hidden lg:flex` 라 내비를 하나도 담지 않는데 그 위에 서브탭 49px 를 더 얹었다 |
| 정보 손실 | 홈 히어로를 없애며 **리포트 기준일이 최상단에서 4섹션 아래로** 밀렸다. "어느 거래일 추천인가"는 이 사이트에서 필수 정보다 |
| 용어 후퇴 | 누구나 아는 `뉴스` 를 내부 용어 `재료` 로 바꿨다(`<title>` 은 "뉴스" 라 h1 과도 불일치 — 색인 대상 화면) |

**교훈: 목적지 수를 줄이지 않고 계층만 얹으면 클릭과 크롬이 함께 늘어난다.** 8탭이 평평한 게 문제가
아니라 목적지 중 일부가 독립 화면일 가치가 없는 것이 문제였다. 다시 손댈 땐 **계층 추가가 아니라
화면 병합**으로 접근한다(검토했던 안: 섹터→시장 병합 · 콘텐츠→뉴스 하단 · 리포트 달력→종목 날짜줄
버튼 ⇒ 5개 화면 전부 1클릭, 서브탭 바 불필요).

같은 턴에 함께 만들었다가 원복된 것: 홈 메인 슬롯을 legacy 점수 1위(`강력 매수`)에서
**검증된 룰의 픽**(`selected=1` + `rule_names`)으로 바꾸는 안. 실측으로 빈 화면 위험은 없었다
(`daily_stock_report` 최근 30 영업일 중 7/29~8/7 **8일 연속** 룰 픽 존재, 8/4~8/7 은 selected 10개 전부.
0인 22일은 live selector 룰 승격 이전 구간). **표시 순서를 룰 수 내림차순으로 두면 대표 카드가 점수
6위 종목이 된다** — 즉 점수 순위와 실제 선정 근거가 어긋난다는 사실이 화면에 드러난다. 구조 원복과
함께 되돌렸지만, 데이터는 이 방향이 가능함을 보여주므로 재시도 시 이 실측을 재사용한다.

## '룰 선정' 배지 (2026-07-29)

hybrid 모드는 점수 순위와 무관하게 종목을 뽑는데 목록은 표시 순번(1,2,3…)을 매기므로, 배지 없이는
점수로 뽑힌 것처럼 읽혔다 — **실측 점수 62위가 화면에서 "10위"로 표시**됐다.
→ 배지 + 부제에 `점수 N위` 병기. 카드 배지는 카드 전체가 이미 `Link` 라 링크 불가해서 룰로 가는 링크는
리포트 상세에만 둔다. 상세 칩은 **한글 제목**(`edge_rule.title`)을 쓰고 코드 슬러그는 링크 경로로만
남긴다(사용자 화면에 내부 식별자를 노출하지 않는다는 `/lab` 용어 원칙).

## 실험실 화면 (`/lab`)

### 검증 중 / 실전 적용 시각 구분
회색조+진행바(모의) vs 컬러(실전) — "모의 성적 ≠ 실탄"을 시각으로 구분한다.

### 2026-08-04 — 판정 종결 전략을 최하단 접힘 섹션으로 (사용자 요청)
진행도 내림차순 정렬 때문에 **게이지가 꽉 찬 종결 전략이 목록 맨 위**에 올라와 승격 임박처럼 읽혔다.
- 카드는 '심사 중' 대신 판정 결과(판정 탈락·재현 실패)를 찍고 사유를 한 줄로 남긴다.
  status 는 candidate 그대로라 모순되는 '검증 중' 배지를 숨긴다.
- 요약 스트립에도 '판정 종결' 타일을 추가하고 '검증 중'·'검증 통과' 집계에서 제외했다 — 종결 전략이
  게이트를 통과한 채 남아 '검증 통과' 숫자를 부풀리고 있었다.
- `decisionLabel` 의 'experimental 정책이면 숨김' 예외를 제거했다 — 평가기는 정책과 무관하게 판정
  일정을 실행하므로 그 예외가 곧 '종결을 숨기는' 원인이었다.
- 판정 여부는 `lib/edge.isDecided` 단일 소스.

### 측정용(benchmark)을 파이프라인 밖으로
승격 게이트 전면 면제라 `promo_eligible` 이 늘 true → 진행률을 보여주면 투입 대기처럼 오해된다.
상태 배지·진행바·'검증 통과' 배지를 숨기고 별도 섹션·요약 타일로 뺐다(`lib/edge.isMeasurementOnly`).
단 '종료'는 수명 정보라 측정용에도 표시한다.

### 카드 높이 통일
검증 상태 슬롯(상태·진행바·설명 3줄)을 조건부로 넣었더니 '남은 조건'이 있는 카드만 키가 커져 그리드가
들쭉날쭉했다 → 설명이 없으면 공백 한 줄이라도 **항상** 렌더한다.

### 서버가 판정, 화면은 렌더링만
프론트가 `min_sample` 로 진행률을 재추정하다 그 조건이 게이트에서 빠지자 **'진행바는 꽉 찼는데
검증 중'** 불일치가 생겼다 → 조건 판정은 서버만 하고 화면은 `promo_eligible`·`promo_blockers`·
`decision_stage` 를 받아 렌더링만 한다(진행바는 거래일 축적만 표시).
