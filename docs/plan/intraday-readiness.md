# 장중매매(intraday) 구조 준비도 점검 (2026-08-04)

> 상태: **점검만 완료 · 코드 변경 없음.** 현행 코드는 "하루 1사이클(오후 매수 → 익일 시가 청산)"
> 전제로 설계돼 있다. 이 문서는 그 전제가 **어디에 박혀 있는지**를 파일·라인 근거로 고정하고,
> 자금 리스크가 낮은 순서로 이관 경로를 남긴다. 구현은 각 단계 착수 시점에 별도 승인/문서로 진행한다.
>
> 배경: 실시간 시세 계층은 2026-07-31(워커 WS 전환, `realtime-ws-migration.md`)과
> 2026-08-04(대시보드 SSE, 같은 문서 §4-1)로 이미 틱 단위가 됐다. 남은 문제는 시세가 아니라
> **상태·멱등·리스크 계층**이다.

| 계층 | 준비도 |

## 2. 구조적 블로커 (우선순위)

### ① 멱등키가 "거래일 1사이클" 전제 — 가장 치명적
- `trading/core/execution_engine.py:40` `idempotency_key = {trade_date}:{signal_id}:{side}`
- 같은 파일 `:205` 매도는 `{date}:0:sell:{tag}:{stk_cd}`
- 키를 풀어주는 경로는 **거부**(`repository/order.mark_sent` → `:x{id}` 부착)와
  **소멸 주문 정리**(`void_dead_order` → `:dead:{id}`)뿐이다.

⚠️ 즉 **성공한 매도는 그 키를 영구 점유**한다 → 같은 거래일·같은 종목의 2회차 청산은
`중복 매도 스킵 (idempotency)` 로그 한 줄만 남기고 **조용히 실행되지 않는다**. 하루 1왕복
설계에서는 이게 정확히 원하는 동작(cron 재실행 안전)이지만, 장중매매에서는 정상 동작이
사라지는 가장 위험한 실패 형태다.

→ 키에 **사이클 식별자**가 들어가야 한다: `{date}:{cycle_id}:{side}:{stk_cd}`.
cycle_id 는 ②의 라이프사이클 엔티티 PK 에서 나온다. `execution_engine.py` 는 민감 파일이므로
수정 전 사용자 확인 + 변경 내용 명시가 필요하다.

### ② 상태 모델이 "일 단위 계획"
- `trading/sql/2. create_table.sql` — `settle_plan` PK = **(trade_date, stk_cd)**, `position` PK = stk_cd
- 하루에 같은 종목을 두 번 잡으면 계획 행이 충돌한다(두 번째 사이클의 스탑선을 담을 자리가 없다)
- 라운드트립 짝짓기가 날짜 기반: `repository/order.latest_buys_before` = "매도일 0시 **이전** 최신 매수"
  → **당일 왕복은 짝이 안 맞는다**. 대시보드 모달 구간 `_trade_window`(매수날 15:00~매도날 10:00)도
  장중 사이클에는 의미가 없다
- `position` 자체는 문제 없다: 전량 매도 후 qty=0 행이 남고 재매수 시 평단이 새로 계산된다
  (`repository/position.apply_buy_fill`)

→ **`position_cycle`(진입→청산 라이프사이클)** 엔티티가 필요하다:
`entry_ts · entry_price · qty · stop_price · target · exit_ts · exit_reason · status`.
`settle_plan` 은 "종가베팅 사이클"이라는 특수형으로 흡수하는 것이 최소 변경이며, ①의 cycle_id 도
여기서 나온다. PK 변경 = 마이그레이션 SQL 필요.

### ③ 시그널 채널이 "하루 1행"
- `trade_signal` UNIQUE **(trade_date, stk_cd)** + 단일 status 컬럼
- 장중 신호는 같은 종목이 하루에 여러 번 나오고, **트리거 종류·발생 시각·유효기간(TTL)** 을 가진다
- 생산자(jongalab) 쪽 성격도 배치(종가 1회 적재) → 상시 판정으로 바뀐다

→ 별도 테이블(`intraday_signal`) 또는 `trade_signal` 키를 (trade_date, stk_cd, trigger_ts) 로 확장.
두 도메인의 유일한 결합점이라 스키마 변경 시 jongalab 쪽 생산자와 함께 움직여야 한다.

### ④ 리스크 한도가 회전율을 전제하지 않음
`trading/core/risk_engine.py`:
- `MAX_ORDERS_PER_DAY`(기본 20, **매수만** 카운트)가 즉시 병목 — 왕복 10회면 소진
- 일일 손실 판정은 **실현손익만** 본다 → 초과 시 서킷브레이커 = 킬스위치 전면 ON(수동 해제).
  장중엔 "N분 쿨다운 후 재개" 같은 단계적 제어가 필요하다
- **종목별 재진입 쿨다운·일일 왕복 상한이 없다**(코드 전수 확인 — `SELL_RETRY_COOLDOWN_SEC` 는
  매도 *재전송* 간격이지 재진입 제한이 아니다). 손절 직후 재매수로 수수료·세금만 나가는 churn 이
  구조적으로 열려 있고, 이는 최상위 목표(잃지 않고 꾸준히)와 정면 충돌한다
- 총노출(gross exposure) 한도가 없다 — `MAX_NOTIONAL_PER_NAME`·`MAX_POSITIONS` 는 현재
  한도 미적용(execution_engine 폴백 사이징용으로만 남아 있음). 시드 25% 캡은 *한 번의 배분 패스*
  안에서만 작동하므로, 장중 반복 진입에는 아무 제약이 되지 않는다

→ `risk_engine.py` 도 민감 파일이다. 필요한 신규 한도: 종목별 재진입 쿨다운, 종목별/전체 일일
왕복 상한, 총노출 상한, 단계적 브레이커(전면 킬 대신 쿨다운).

### ⑤ 프로세스 모델(창 cron)과 포지션 소유권
- 전 워커가 PM2 cron 창 안에서만 살고 창이 끝나면 스스로 종료한다
  (monitor 08:00~09:30 / buy 15:00·19:30 / settle 08:03·09:03·09:28)
- watchdog 은 "마감 시각까지 **완료 마커**가 있어야 한다" 방식(`workers/watchdog.py:34`
  `CRITICAL_WORKERS`) — 상시 워커에는 맞지 않는다 → **하트비트 신선도 감시**로 확장해야 한다
- ⚠️ **소유권**: 지금은 창이 겹치지 않아 "한 시점에 한 워커만 매도"가 **스케줄로** 보장된다.
  장중 전략 워커와 하드손절 감시가 동시에 살면 같은 종목에 **이중 매도**(보유 3주에 3+3주 시도)가
  가능하고, tag 가 다르면 멱등키도 이를 막지 못한다

→ 가장 단순한 해법: **집행(주문) 권한을 단일 프로세스에 두고, 전략은 신호만 큐에 넣는다.**
지금 jongalab→trading 결합 패턴을 장중으로 연장하는 것이라 새 개념을 도입하지 않는다(설계 원칙 3).

## 4. 권장 순서 (자금 리스크 낮은 것부터)

1. **shadow 장중 워커** — 주문 없이 상시 루프를 돌려 신호·시세·호가 스냅샷만 적재하고 사후 채점.
   상시 프로세스 운용, 유니버스 크기, 0D 필요성을 **실측으로** 확정한다. 자금 리스크 0.
   (수급 관측·뉴스 라벨에서 이미 쓰는 "먼저 쌓고 나중에 검증" 패턴과 동일)
2. **WS 허브 승격** + 0D 호가 구독 — 단일 세션이 구독을 소유하고 소비자에게 팬아웃.
   여기서 90 상한·동시 세션 미검증 문제를 구조적으로 해소한다. `price_stream` 은 자기 세션을 버리고
   허브 소비자로 전환(표시 전용 격리·refcount 는 유지).
3. **`position_cycle` 도입 → 멱등키에 cycle_id**(①②). `execution_engine.py` 수정 = 사용자 승인 필요.
4. **리스크 확장**(④): 재진입 쿨다운 · 일일 왕복 상한 · 총노출 · 단계적 브레이커.
   `risk_engine.py` 수정 = 사용자 승인 필요.
5. **집행 단일화**(⑤) + watchdog 을 하트비트 신선도 감시로 전환.
6. **대시보드**: phase(창) → 세션 기반, RoundTrips·차트 구간을 cycle 기반으로.

1·2 는 자금 경로를 건드리지 않고, 3·4 가 민감 파일 변경이다. 3·4 없이 장중 진입을 켜면
**2회차 청산 누락(①)** 과 **churn 무제한(④)** 이 동시에 열리므로, 이 둘은 live 진입의 전제 조건이다.

## 5. 경고

장중매매는 회전율을 올리는 방향이고, 그만큼 **수수료·세금과 휩쏘가 구조적으로 커진다.**
현행 표본에서 이미 나온 결론들과 충돌하지 않는지 매 단계 확인할 것:
- 2026-07-18 분봉 백테스트: 현행 하드손절이 모든 변형(확인틱·2단계·개장대기)보다 우수했고,
  휩쏘 반등은 09:28 이후라 실현 불가였다 → "더 촘촘한 개입"이 자동으로 이득이 아니다
- 2026-08-03: 갭상승 잔량 트레일링은 65/66건 손해(-0.45%p/건), '오래 들기'는 아웃샘플 재기각

→ 장중 전략은 **1단계 shadow 로 자체 표본을 만든 뒤**에만 live 승격을 논한다. 엣지 검증 없이
켜는 것은 목표(잃지 않고 꾸준히 1%)에 대한 순손실 베팅이다.
