# jongalab/frontend — 대시보드 (Next.js)

jongalab 백엔드(`:8000`)의 리포트·종목·수급·테마·콘텐츠를 보여 주는 **모바일 우선** 웹 대시보드.
Next.js 16 App Router + React 19 + Tailwind 4 + recharts.

> **모바일 우선이 1순위 규칙이다.** 이 대시보드는 모바일에서 자주 쓰인다. 모든 UI 는 작은 화면을
> 먼저 만족시키고 `sm:`/`md:` 로 확장한다. 데스크탑만 보고 끝내지 말 것.

## 코드 구조
```
frontend/
├── app/             # App Router 페이지 (라우트 = 폴더)
├── components/      # 재사용 UI·차트 카드 (recharts)
├── lib/api.ts       # fetch 래퍼 (API_BASE = :8000)
└── types/index.ts   # 타입 정의 — 백엔드 응답 shape 과 일치시킨다
```

## 규칙
- 차트는 recharts, 아이콘은 lucide-react, 스타일은 Tailwind 4 유틸리티.
- 새 카드 컴포넌트는 `/new-card` 스캐폴드를 사용한다.
- 타입은 `types/index.ts` 에 정의하고 백엔드 응답과 어긋나지 않게 유지한다.
- admin 변경(POST)은 클라이언트에서 직접 백엔드를 부르지 않고 **로컬 라우트 핸들러**(`app/api/*`)를
  거친다 — 서버에서 httpOnly 세션 쿠키를 백엔드 인증 헤더로 주입한다(`lib/api.adminAuthHeaders`).

## 주요 화면
- `/news` — **뉴스 탭**. 2026-08-03 구조 재설계(그 전에는 '뉴스 재료 탭'). 화면은
  **요약 타일 → 종목별 재료 → 헤드라인 스트림** 3층 + 사이드 '뉴스가 몰린 종목' 랭킹이고,
  상단에서 **날짜를 이동**한다(`?date=YYYY-MM-DD`, 기본값은 오늘이 아니라 **가장 최근 리포트일** —
  휴장일·장 시작 전에 통째로 빈 화면이 되지 않게). 재설계 이유는 아래 세 가지였다.
  1. **시간축·원문이 없었다** — 뉴스 탭인데 헤드라인이 한 줄도 없었다. 예전 결정("속보 피드는
     의도적으로 두지 않는다")을 뒤집고 `news/NewsStream` 을 넣되, 파이어호스 문제는 ① 기사 단위로
     접고(백엔드가 `source_url` 로 종목 중복 행을 합침) ② 시세 기사를 기본으로 숨기고
     ③ 큐레이션 계층 **아래**에 두는 것으로 막는다. 데이터: `/api/news/stream`(40건씩 '더 보기',
     클라 호출은 로컬 프록시 `app/api/news/stream`).
  2. **모수가 너무 좁았다** — 재료 목록은 그 날 후보 종목만 다루는데, 실측 2026-08-03 기준
     뉴스가 붙은 종목 131개 중 후보와 겹친 건 7개뿐이었다(화면에 카드 7장). 후보 밖 종목은
     `news/NewsBuzzRail`(`/api/news/heat?date=`)이 덮고, 후보인 종목엔 '후보' 배지를 달아
     두 목록의 관계를 드러낸다.
  3. **묶는 축이 사용자 축이 아니었다** — 지속성 등급 3그룹으로 미리 갈라 놓으면 실측상 절반
     이상이 '판정 보류'로 떨어진다(07-31 36건 중 22건, 07-28 은 18건 전부). `news/MaterialBoard`
     에서 **단일 목록 + 필터(등급·선정·재료 유형 칩) / 정렬(뉴스 많은 순·등락률·후보 순위) / 검색**
     으로 바꿨다. 기본 정렬은 뉴스 많은 순(배수). 행을 누르면 판정 근거가 있는
     `/reports/{date}/{code}` 로 간다.
  ⚠️ 지속성 라벨은 여전히 **candidate rule 표본(관찰 전용·미검증)** 이다. 필터 칩으로 올린 것은
  축이지 신뢰도가 아니다 — 예전 헤더의 4줄 면책 문단은 모바일 첫 화면을 다 먹어 접이식 안내로
  옮겼지만 문구("매수 신호가 아니고 실매매에 개입하지 않습니다")는 닫힌 상태에서도 보이게 남겼다.
  데이터: `/api/news/materials` + `/api/news/heat?date=` + `/api/news/stream`
  + `/api/stock-report/dates`(날짜 이동은 영업일 목록 위를 걷는다).
- **재료 칩 `components/MaterialBadge.tsx`** — 연속/중립/소진/미판정 공통 칩 + `materialAxisLabels`
  (사실 4축을 사람 말로: "다음 일정 남음 · 수치 미확정 · 산업 사이클 · 첫발표").
  **색을 손익 방향(빨강/파랑)으로 쓰지 않는다** — 미검증 라벨이 매수 신호로 읽히면 게이트 통과를
  '검증됨'으로 오독하는 문제의 UI 버전이 된다. 배경은 중립 회색, 방향은 화살표로만, title 에 '미검증'.
  쓰는 곳: 홈 카드(`today/NewsHeat`)·`/news`·리포트 상세 뉴스 재료 섹션.
- 홈 **'오늘 새로 뜬 재료'** 카드(`today/NewsHeat`) — 예전 '뉴스 재료'(언급 건수 랭킹)를 **자기 기저
  대비 배수** 정렬로 교체했다. 건수 랭킹은 시총 랭킹이라 매일 같은 대형주만 보였다(실측 상단 고정
  하이닉스·현대차·삼성전자). 근거(건수·평소 N건/일)를 함께 보여줘 값을 검증할 수 있게 한다.
- 리포트 상세 **뉴스 재료 섹션** — 등급 칩 + 4축 + **판정 근거 문장**(`news_label_reason`)을 노출한다.
  등급만 보여주면 왜 그렇게 판정됐는지 알 수 없어 **화면에서 오탐 감사가 안 된다**(공시 분류기 오탐
  5종을 잡은 방식이 육안 감사였다). 후속 재료 실현 일수도 함께 표시.
- 종목 상세 **'오늘의 뉴스'**(`TodayNews`) — 시세보도 기사("급등/상한가/특징주" 류, 실측 21%)는
  `details/summary` 로 접어 재료 기사가 묻히지 않게 한다(서버 컴포넌트 유지, CSS-only 토글).
- **'룰 선정' 배지**(`StockReportCard` + 리포트 상세 헤더, 2026-07-29) — `rule_names` 가 있는 종목은
  실험실 룰(hybrid 모드)이 **점수 순위와 무관하게** 뽑은 종목이다. 목록은 표시 순번(1,2,3…)을 매기므로
  배지 없이는 점수로 뽑힌 것처럼 읽힌다(실측 점수 62위가 "10위"로 표시) → 배지 + 부제에 `점수 N위`를
  함께 낸다. 카드 배지는 카드 전체가 이미 `Link` 라 링크 불가 → 룰로 가는 링크는 **리포트 상세**에만.
  상세 칩은 **한글 제목**(`edge_rule.title`, 실험실 카드와 같은 이름)을 쓰고 코드 슬러그
  (`f5_prog_persistent`)는 `/lab/[name]` 링크 경로로만 남긴다 — 사용자에게 보이는 화면에 내부
  식별자를 노출하지 않는다는 `/lab` 용어 원칙을 여기서도 지킨다(title 이 없으면 슬러그 폴백).
- **재료 판정 근거 문장**(`lib/news.humanizeMaterialReason`) — LLM 이 낸 `news_label_reason` 에는
  내부 판정 항목명이 섞여 있다(`next_milestone=0`, `amount_locked를 null로`). 판정 프롬프트를
  2026-07-29 고쳐 신규 행은 한글로 오지만 **이미 저장된 행은 소급 불가**라 화면에서 치환한다.
  치환으로 앞말 종성이 바뀌면 조사가 틀어지므로(`수치 확정를`) 목적격·부사격 조사도 함께 교정한다.
  판정 항목을 추가하면 이 치환표에도 넣어야 한다(빠지면 영문 필드명이 사용자 화면에 샌다).
- `/lab` — **전략 실험실**(Edge Ledger, 네비 라벨 "실험실"). **읽기 전용 공개 화면** — 서버
  컴포넌트가 `getEdgeRules()`+각 rule 일별 시계열(+최신 매칭 1일치)을 실어 `EdgeBoard`(클라)로
  내려준다. 상태 그룹(실전 적용→검증 중→종료 접힘→**측정용 기준선**) 카드 + 요약 스트립 + 접이식
  도움말("이 화면은 어떻게 보나요?"). 카드를 누르면 `/lab/[name]` 상세 페이지로 이동해 일별
  막대차트·선정 조건·최근 매칭을 보여준다. 매칭 종목명은 **그 날짜의 리포트 상세**
  (`/reports/[date]/[code]`)로 링크한다(2026-07-29) — 룰이 무엇을 보고 걸렸는지 원본을 확인하는
  경로이고, 반대 방향은 리포트 상세·종목 카드의 '룰 선정' 배지가 `/lab/[name]` 으로 되돌린다.
  검증 중은 회색조+진행바(모의), 실전 적용은 컬러 — "모의 성적 ≠ 실탄"을 시각 구분.
  **측정용(role=benchmark)은 검증→투입 파이프라인 밖**이라 상태 배지(검증 중/적용 중)·검증 진행바·
  '검증 통과' 배지를 모두 숨기고 별도 섹션·요약 타일로 뺀다(승격 게이트 전면 면제라 `promo_eligible`
  이 늘 true — 진행률을 보여주면 투입 대기처럼 오해된다). 판정은 `lib/edge.isMeasurementOnly` 단일
  소스이고, 텔레그램 알림도 `workers/rule_evaluator` 가 benchmark 를 승격·강등 양쪽에서 제외한다.
  단 '종료'는 수명 정보라 측정용에도 표시한다.
  **용어 원칙**: 코드 용어(rule/candidate/predicate/CI)를 노출하지 않는다 — 한국어 라벨·도움말은
  전부 `lib/edge.ts`(STATUS_LABEL·STAT_META·FAMILY_META·condText 컬럼 사전)에서 일괄 관리.
  컴포넌트: `EdgeSummaryStrip`·`EdgeRuleCard`·`EdgeRuleDetailContent`.
- `/admin/edge-rules` — **전략 관리**(admin 탭). 실전 투입(promote)/종료(retire)는 **여기서만**
  한다(공개 화면엔 버튼 없음). 섹션: 검증 통과 대기 → 실전 적용 중 → 검증 중 → **측정용 기준선**
  (종료만 가능 — 기준선 교체는 의도적 수동 작업) → 종료(접힘).
  확인 다이얼로그 후 `app/api/edge-rules/[id]`(admin 프록시, httpOnly 쿠키 주입) 호출 —
  조건 미충족 409 사유를 그대로 표시(게이트는 백엔드 단일 소스). 목록은 `app/api/edge-rules`
  GET 프록시로 조회.

## 개발 / 검증
```bash
npm run dev                       # :3000 dev 서버
npx tsc --noEmit && npm run lint  # 변경 후 필수 검증 (+ 모바일 폭 ≈375px 레이아웃 점검)
```
> 턴 종료 시 변경분은 `npm run build` 후 `jongalab-fe`(PM2)로 자동 반영된다(빌드 실패 시 알림).
> 작업 규칙·가드레일은 루트 [`AGENTS.md`](../../AGENTS.md) 참고.
