# jongalab/frontend — 대시보드 (Next.js)

jongalab 백엔드(`:8000`)의 리포트·종목·수급·테마·뉴스·콘텐츠를 보여 주는 **모바일 우선** 웹 대시보드.
Next.js 16 App Router + React 19 + Tailwind 4 + recharts.

> **모바일 우선이 1순위 규칙이다.** 이 대시보드는 모바일에서 자주 쓰인다. 모든 UI 는 작은 화면을
> 먼저 만족시키고 `sm:`/`md:` 로 확장한다. 데스크탑만 보고 끝내지 말 것.
>
> 이 README 는 **현재 화면 구성과 규칙**만 적는다. 재설계 경위·실측 수치·오독 사고는
> [`docs/history/frontend-ui.md`](../../docs/history/frontend-ui.md) 에 있다.
> 작업 규칙·가드레일은 루트 [`AGENTS.md`](../../AGENTS.md) 참고.

## 코드 구조
```
frontend/
├── app/                 # App Router 페이지 (라우트 = 폴더) + app/api/* 로컬 라우트 핸들러
├── components/
│   ├── pick/            # 추천(홈·리포트·성적) 전용 — PickHero·PickList·RecordStrip 등
│   ├── home/            # 홈 전용 요약 — MarketPulse(시장·주도섹터 카드 줄)·NewsDigest
│   ├── market/          # 시장 탭 — SectorBoard
│   ├── news/            # 뉴스 탭 — MaterialBoard·NewsStream·MentionPulse 등
│   └── ui/              # 공통 프리미티브
├── lib/api.ts           # fetch 래퍼 (API_BASE = :8000) + 추천 조회 헬퍼
├── lib/nav.ts           # 전역 내비 단일 소스 — Navbar 와 하단 탭이 공유
└── types/index.ts       # 타입 정의 — 백엔드 응답 shape 과 일치시킨다
```

## 정보 구조 — 목적지 5개
**종목 추천이 최우선 기능이다.** 홈이 곧 추천 화면이고, 나머지는 그 근거·결과·배경이다.

| 탭 | 경로 | 역할 |
|---|---|---|
| 추천 | `/` | 가장 최근 리포트일의 추천 종목 전체 + 시장 줄(지수·섹터 카드) + 성적·뉴스 요약 |
| 성적 | `/record` | 날짜별 승패 달력 + 누적 승률·평균 수익률 |
| 뉴스 | `/news` | **뉴스** / **콘텐츠** 세그먼트(`?view=content`) |
| 시장 | `/market` | **지수** / **섹터** 세그먼트(`?view=sector`) |
| 실험실 | `/lab` | 선정 규칙 검증 성적 |

- **탭에 항목을 더하지 않는다.** 하단 탭 5칸이 목적지 5개와 정확히 맞아 '더보기' 시트가 없고,
  모든 화면이 1클릭이다. 새 화면이 필요하면 먼저 **어떤 화면과 합칠지**부터 정한다
  (계층을 얹으면 클릭과 크롬이 함께 는다 — `docs/history/frontend-ui.md` 참고).
- 탭에서 내려간 화면은 경로가 살아 있다: `/reports/{date}`(날짜 이동·달력의 목적지),
  `/stocks/{ticker}`(종목별 상시 페이지 — **리포트 이력이 있는 종목만** 색인 대상이다.
  `app/sitemap.ts` 가 리포트에 등장한 종목만 싣고, 콘텐츠·리포트가 둘 다 없는 종목은
  `generateMetadata` 가 `robots: { index: false }` 를 준다).
  인덱스 경로는 리다이렉트한다 — `/stocks`→`/`, `/sectors`→`/market?view=sector`,
  `/feed`→`/news?view=content`.
- **화면 안에서 뷰를 가르는 건 `components/ViewSegment`**(`?view=` 쿼리)로 통일한다.
  탭을 늘리지 않으면서 긴 화면을 나누는 유일한 수단이고, canonical 은 원래 경로 하나로 남는다.
- 관리(`/admin/*`) 진입점은 상단 Navbar 우측 아이콘 하나뿐이다(모바일 포함).

## 규칙
- 차트는 recharts, 아이콘은 lucide-react, 스타일은 Tailwind 4 유틸리티.
- **표면(surface)은 `lib/ui.ts` 의 3단계만 쓴다** — L0 페이지 배경 · `CARD`(페이지 위 카드) ·
  `INSET`(카드 안 블록·차트 트랙). 페이지 배경이 `#F9FAFB` 라 흰 배경만으로는 카드 경계가
  안 보여서, 경계는 배경색이 아니라 **헤어라인 링**이 만든다.
- **강조를 표면 반전(어두운 패널)으로 만들지 않는다.** 라이트모드에서만 강조가 되고
  다크모드에서는 다른 카드와 같은 어두운 상자가 된다. 강조는 **크기·구조**로 준다 —
  히어로 숫자(≥48px, 화면당 하나) · 미터 · 카드 안쪽 한 단 낮은 면(`INSET`).
- **큰 단독 숫자에는 `tabular-nums` 를 쓰지 않는다.** 자릿폭이 `0` 으로 고정돼 헐거워 보인다.
  표·축처럼 세로로 자리를 맞춰야 하는 숫자에만 쓴다.
- **데이터 색은 역할로 고정한다.** 등락·손익 방향 = 빨강(상승)/파랑(하락)/회색(보합),
  크기(순위 아님) = 브랜드 보라 막대(light `purple-800` / dark `purple-300`), 앱 강조(점수·링크) = 남색.
  ⚠️ **남색·밝은 보라를 막대에 쓰지 말 것** — 하락(파랑)과 색맹 조건에서 구분되지 않는다
  (indigo↔blue ΔE 2.8 · purple-600↔blue ΔE 1.3 deutan). 막대에 쓸 보라는 파랑과 명도가 갈리는
  진한/옅은 양끝 스텝만 쓴다(실측은 `docs/history/frontend-ui.md`).
- 막대·미터에는 **숫자 라벨을 항상 함께** 낸다(색·길이 단독 금지). 두 구간을 잇는 막대는
  사이에 2px 틈을 둬 경계를 형태로도 낸다.
- **페이지 타이틀은 `{화면 이름} - {검색 키워드}` 한 규칙으로 맞춘다.** 앞은 **화면 h1 과 같은
  짧은 이름**(`"추천 성적"`), 뒤는 그 화면이 답하는 **실제로 검색되는 말**(`"종가베팅 승률·수익률"`)
  이다. h1 이름만으로 검색어가 되면(`"종목 뉴스"` 처럼) 부제를 생략한다.
  화면 이름을 앞에 두는 건 탭·브라우저 탭에서 어느 화면인지 먼저 읽히게 하기 위한 것이고,
  부제는 화면에 실제로 있는 내용만 쓴다(없는 걸 적으면 제목과 본문이 어긋난다).
  브랜드 접미사는 루트 레이아웃의 `title.template`(`"%s | 종가랩"`)이 붙인다.
  페이지에서 `"| 종가랩"` 을 직접 붙이지 말 것.
  예외는 **루트 `app/page.tsx`** 하나다 — 루트 page 는 자기 layout 의 template 적용 대상이
  아니라서 `title: { absolute: "오늘의 추천 | 종가랩" }` 로 전체 문자열을 쓴다(구분자를 바꾸면
  여기도 같이 바꾼다).
  관리 화면은 `app/admin/layout.tsx`(서버, 메타데이터 전용)가 `"관리"` + `noindex` 를 준다.
- **리포트 페이지 제목은 `{이름} - {YYYY.MM.DD}`** — 검색 의도 키워드가 앞, 날짜는 뒤다
  (`"한미반도체 투자분석 - 2026.08.18"` · `"종가베팅 추천 10종목 - 2026.08.18"`).
  종목 상세는 **"투자분석"** 을 쓴다 — "추천 근거"는 그 자체로 검색되는 말이 아니다.
  날짜를 앞세우거나 description 에 순매수 금액을 나열하면 "종목명 날짜 종가" 류의
  **시세 조회 쿼리**에만 걸리고 클릭으로 이어지지 않는다. description 은 수치 나열이 아니라
  "왜 골랐나"를 쓴다. 근거: `docs/plan/seo/search-visibility.md`.
  날짜 없는 `/stocks/{ticker}`(상시)는 `"{종목명} 종목 분석"` 으로 둔다 — 날짜가 붙는 리포트
  상세와 역할을 가르기 위한 것이다(상시 질의는 상시 페이지가 받는다).
- **파비콘은 `app/icon.png`(192²) · `app/apple-icon.png`(180²) 파일 규약으로만 낸다.**
  루트 `metadata.icons` 를 선언하지 않는다 — 규약 파일이 해시 URL·불변 캐시 헤더를 받는다.
  크기는 **48의 배수인 정사각형**이어야 구글이 검색 결과에 쓴다. `public/logo.png`(2048²/935KB)를
  파비콘으로 가리키면 매 페이지가 그 용량을 받는다(Navbar 로고는 next/image 가 24² 로 최적화).
- 새 카드 컴포넌트는 `/new-card` 스캐폴드를 사용한다.
- 타입은 `types/index.ts` 에 정의하고 백엔드 응답과 어긋나지 않게 유지한다.
- admin 변경(POST)은 클라이언트에서 직접 백엔드를 부르지 않고 **로컬 라우트 핸들러**(`app/api/*`)를
  거친다 — 서버에서 httpOnly 세션 쿠키를 백엔드 인증 헤더로 주입한다(`lib/api.adminAuthHeaders`).
- **조건 판정은 서버만 한다.** 화면은 백엔드가 준 판정값(`promo_eligible`·`promo_blockers`·
  `decision_stage` 등)을 렌더링만 한다 — 프론트에서 게이트 조건을 재추정하면 서버와 어긋난다.
- **용어 원칙**: 코드 용어(rule/candidate/predicate/CI)와 내부 식별자(`f5_prog_persistent` 류)를
  사용자 화면에 노출하지 않는다. 한국어 라벨·도움말은 `lib/edge.ts`(STATUS_LABEL·STAT_META·
  FAMILY_META·condText 컬럼 사전)에서 일괄 관리한다.
- **미검증 라벨에 손익 색(빨강/파랑)을 쓰지 않는다.** 관찰 전용 라벨이 매수 신호로 읽히면 안 된다 —
  배경은 중립 회색, 방향은 화살표로만 표시하고 title 에 '미검증'을 남긴다.
- **문체 원칙**: 사용자에게 보이는 모든 설명·도움말·빈 상태·면책 문구는 **`-요` 체**(토스 스타일)로
  쓰고, **중학교 1학년이 읽어도 이해되는 수준**으로 풀어 쓴다. 통계·금융 용어를 그대로 쓰지 않고
  뜻을 문장으로 설명한다(신뢰구간 하한 → "운이 나빴을 경우까지 감안해 낮춰 잡은 값", 시가 →
  "아침 첫 가격"). 도메인 용어(수급·종가베팅·테마)는 유지하되 처음 나올 때 괄호로 풀어 준다
  (`수급(기관·외국인 매수)`). 라벨·배지·표 헤더는 짧은 명사구를 그대로 쓴다.

## 주요 화면

### `/` — 오늘의 추천 (홈·랜딩)
가장 최근 리포트일의 **선정 종목 전체** + 시장 지표. 기준일은 '오늘'이 아니라 최신
리포트일이다(휴장일·장중에 화면이 통째로 비지 않게).

배치는 **추천이 본체, 지표는 카드 2장**이다. 지표를 픽 목록 위에 두되 짧게 묶어,
"한눈에 들어온다"와 "추천이 첫 화면을 지킨다"를 동시에 만족시킨다.

```
헤더(PickHero)
시장 카드 2장(MarketPulse: [시장 = 코스피·코스닥·S&P 500] [주도섹터 1·2위])
매크로 경고(MacroEventNotice)
┌ lg+ 2단 ──────────────────┬──────────────┐
│ 1등 픽 카드 (전체 폭)        │ 성적(RecordStrip) │
├───────────────────────────┼──────────────┤
│ 2·3·4등… 카드 그리드         │ 뉴스(NewsDigest)  │
│ 이 날 결과 + 시드 배분        │                 │
└───────────────────────────┴──────────────┘
모바일(<lg)은 DOM 순서 그대로 성적 → 추천 → 뉴스 로 쌓인다
```

**좌우 상단 정렬은 두 값이 같아야 성립한다.**
1. **1등 픽 카드와 성적 카드의 높이** — 서로 다른 열/행이라 CSS 로 맞출 수 없어 `lib/ui.HERO_ROW_H`
   (`lg:min-h-56` = 224px) 라는 **공통 하한**을 둘 다 쓴다. 어느 한쪽에 줄을 추가해 이 값을 넘기면
   그만큼 우측 뉴스 카드 상단이 좌측 2·3·4등 줄과 틀어진다 — 그땐 이 상수를 함께 올린다.
   1등 카드가 하한을 채우는 방법은 **종목명 확대(`lg:text-4xl`) + 아래 선정 근거 블록** 둘뿐이다.
   ⚠️ 가격·점수·배지까지 함께 키우지 않는다 — 카드가 통째로 확대돼 보인다(2026-08-11 되돌림).
   하한보다 짧은 카드는 `justify-between` 으로 남는 공간을 줄 사이에 분산한다.
   하한보다 짧은 성적 카드는 `justify-between` 으로 남는 공간을 줄 사이에 분산한다
   (아래로 몰면 그게 곧 '카드 아래가 비었다'가 된다).
2. **세로 간격** — 바깥 그리드도 카드 그리드 안쪽과 같은 `gap-3` 을 쓴다(가로만 `lg:gap-x-6`).
   뉴스는 `성적 + 세로 간격` 아래, 좌측 2행은 `1등 카드 + gap-3` 아래에서 시작하기 때문이다.

- `pick/PickHero` — 기준일 → `h1 + 선정 근거 한 줄`(같은 줄) → 접이식 면책.
  **기준일이 최상단**이다("어느 거래일 추천인가"는 이 사이트의 필수 정보).
  홈에는 날짜 이동을 두지 않는다(`dates` 미전달) — 날짜를 오가는 건 아카이브의 역할이다.
- `home/MarketPulse` — **카드 2장**: `시장`(지수 3 = 국내 2 + 미국 1) / `주도섹터`(1·2위).
  성격이 다른 둘을 각자의 카드에 넣어 **라벨을 카드당 한 번만** 둔다.
  **카드 안쪽은 가로(열) 배치다** — 카드가 가로로 길어 항목을 세로로 쌓으면 오른쪽 폭이 남고
  카드만 길어진다. 열 하나가 항목 하나이고, 열 안에서만 두 카드가 같은 3줄 리듬을 쓴다:
  지수 `이름 / 지수값 / 등락률`, 섹터 `순위 / 테마명 / 등락률+종목수`.
  지수 열은 아래 절반에 `Sparkline`(시장 탭과 같은 언어), 섹터는 시계열이 없어 그 자리를 비운다.
  모바일은 카드가 각자 전체 폭(1열 스택)이라 안쪽 열이 뭉개지지 않고, `sm:` 이상에서 나란히
  놓으며 열이 하나 더 많은 지수 카드에 3:2 로 폭을 더 준다. 지수는 외부 API 라 `Suspense`
  스트리밍(`IndexCard`).
  섹터 카드의 이름 줄 곁말은 상위 2섹터 구성종목과 오늘 픽의 교집합 수
  (`추천 N종목 포함` / 겹치지 않으면 그대로 적는다 — 테마 코드는 `_` 접미사를 떼고 비교).
  곁말을 카드 아래 각주로 한 줄 더 두지 않는 이유는 두 카드 높이가 어긋나기 때문이다.
  ⚠️ **상한은 카드 2장이다** — 큰 차트·필터·펼침을 붙이지 말 것. 넘어서는 내용은 `/market` 에 둔다.
- `pick/MacroEventNotice` — 오늘 밤 발표 경고. 홈에만 둔다.
- `pick/PickList` → `StockReportCard` — **백엔드가 준 순서를 그대로 쓴다**(규칙 수 내림차순 →
  rank_no 오름차순). 화면에서 다시 정렬하지 않는다.
  맨 앞 한 장은 **전체 폭 강조 카드**로 낸다(3열에서 1 + 9 = 4행). 전체 폭 카드가 중간에 끼면
  앞줄에 빈칸이 남으므로 반드시 첫 장이어야 하고, 규칙 선정이 없는 날은 강조하지 않는다.
  그 한 장은 **데스크탑에서만 아래에 '선정 근거' 블록**(`INSET`, 카드 전체 폭)이 붙는다 —
  규칙마다 한 줄로 `한글 제목 · 초심자용 설명 · 상태 라벨`(`lib/edge.STATUS_LABEL`)을 내고,
  블록은 **규칙 수와 무관하게 항상 2줄**이다(`ruleCardCount`) — 규칙 1~2개면 규칙 줄만,
  3개 이상이면 규칙 1줄 + '외 N개' 한 줄. 3줄이 되면 `HERO_ROW_H` 하한을 넘겨 성적 카드와
  상단 정렬이 깨진다. 규칙이 하나뿐인 날은 설명을 2줄까지 늘려 아래 여백을 메운다.
  **좌우 열로 쪼개지 않는다**(2026-08-11 2단 안 기각).
  안쪽 여백은 일반 카드보다 한 단 넓지만 **가로만** 넓다(`px-5 pl-6 lg:px-6 lg:pl-7`) —
  세로를 키우면 카드 높이가 그대로 커져 같은 정렬이 깨진다.
  데스크탑에서는 상단 '규칙 N개' 배지와 근거 한 줄이 이 블록과 겹치므로 `lg:hidden`,
  점수 배지는 가격 열 아래로 간다(모바일은 그 둘이 그대로인 1열 카드).
  ⚠️ 블록에 **룰 성적 수치(승률·평균 수익)는 넣지 않는다** — 종목 옆에 붙으면 그 종목의
  확률로 읽힌다. 성적은 실험실 탭(`/edge`)이 맥락과 함께 낸다.
  룰 원본은 `lib/api.getRuleMap()`(목록 화면이 이미 부르던 공개 엔드포인트)에서 오고 추가 왕복이 없다.
  span 은 열 수와 무관하게 `col-span-full` 이다 — 특정 열 수에서만 걸면 그 밖의 구간에서 배지 줄만큼
  높은 1등 카드가 같은 행의 우측 카드를 늘려 아래에 빈 공간이 남는다.
  **'이 날 결과' + 시드 배분 줄은 목록 아래**다 — 위에 두면 홈 2단에서 좌측 첫 카드가 그만큼
  내려가 우측 성적 카드와 시작선이 어긋나고, 마무리 수치라 읽는 순서로도 아래가 맞다.
  검색·정렬 컨트롤은 없다(하루 10종목 규모). 열 수는 화면 폭이 아니라 **목록이 받은 폭**을
  따른다(`@container` + `@md:`/`@4xl:`) — 홈은 사이드바에 폭을 내주고 리포트 화면은 전체 폭을 쓴다.
- `pick/SeedAllocator` — **버튼 + 모달**. 목록 아래 결과 줄 우측(`PickList` 의 `action`)에 붙는다.
  본문 섹션이면 세로 공간을 크게 먹어 추천 목록을 밀어낸다.
  배분 로직은 `trading/core/seed_allocator.py` 의 **전량 미러**다 — 표 수(규칙 수 + 점수 top-N
  1표) 비례 목표금액 · 표 수 우선 TOP_N 컷 · 종목당 캡 25% · 고가주 첫 1주 예외 · 표 대비
  최소투입 그리디. 상수는 trading **기본값**으로 고정한다(프론트는 trading `.env` 미접근)
  — 실거래가 `.env` 로 튜닝돼 있으면 그만큼 달라진다. ⚠️ 한쪽만 고치면 미리보기가 거짓말이 된다.
- `pick/RecordStrip` — 홈의 **히어로 수치**. 표면은 다른 카드와 같고, 48px 승률 숫자 ·
  승률 미터(rose 채움 + rose 15% 트랙) · 안쪽 `INSET` 블록(평균 갭·평균 실체결)의
  **구조**로만 강조한다. 화면의 유일한 대형 숫자다(h1 도 30px). 누르면 `/record`.
- `home/NewsDigest` — 뉴스가 몰린 종목 5건 **세로 목록**(좁은 사이드바에서도 읽히게).
  배수(`surprise`)를 **브랜드 보라 막대**로 낸다(light `purple-800` / dark `purple-300`) —
  손익이 아니라 화제성이라 빨강/파랑을 쓸 수 없고, 밝은 보라(purple-500/600)·남색은 하락(파랑)과
  색맹 조건에서 구분이 안 된다. 막대 옆에는 `lib/news.newsHeatLabel` 라벨을 항상 함께 낸다
  (뉴스 탭과 같은 문구 — 아래 '뉴스량 라벨' 참고). 창이 **최근 24시간**이라(뉴스 탭은 하루)
  캡션에 창과 기준을 못 박는다.
  ⚠️ 여기에 큰 카드·차트·필터를 붙이지 말 것 — 홈이 다시 종합 대시보드가 되면 추천이 묻힌다.

### 픽 카드 (`StockReportCard`) — 홈·`/reports/{date}` 공유
4줄 고정 구조다: `종목명+현재가` / `섹터·거래대금+등락률` / `선정 근거 + 점수` / `배지 + 갭 결과`.
- 좌측 세로 띠는 **당일 등락 방향**이다 — 상승 옅은 빨강 / 하락 옅은 파랑 / 보합 회색.
  옅게 두는 이유는 카드 배경(갭 결과)과 등락률 pill 이 이미 같은 적/청 계열이라, 띠까지
  진하면 셋이 색으로 경쟁하기 때문이다. 색 단독 표시가 아니라 등락률 pill 의 부호가 라벨을 겸한다.
- 당일 등락률은 **색면 pill**이다. 카드마다 값이 달라 목록에서 카드를 구분하는 1차 단서다.
- **개별 종목 카드에는 스파크라인을 넣지 않는다**(2026-08-10 시도 후 "과하다"로 철회).
  10장이 쌓이는 목록에서 선이 반복되면 지수 카드의 그래프가 오히려 안 보인다.
근거·점수·갭을 각각 별도 블록으로 두던 구조를 한 줄씩으로 합쳤다 — 홈에서 카드 10장이
세로로 쌓이는 만큼 시장 지표가 화면 밖으로 밀리기 때문이다. **줄을 늘리지 말 것.**
- **표시 순번(1,2,3…)을 매기지 않는다.** 목록 정렬이 규칙 수 우선이라 순번을 붙이면 점수
  순위와 어긋난 채 '랭킹'처럼 읽힌다. 순위 대신 **점수 + 선정 근거 줄**을 낸다.
- `featured` 카드(맨 앞 한 장)는 **`규칙 N개가 겹쳐 고른 종목` 배지 + 남색 링 + 큰 종목명**이다.
  배지에는 **기준만** 적는다 — '유력'·'강력 추천' 같은 예측 문구를 쓰지 않는다.
- 근거 줄에는 룰의 **한글 제목**(`edge_rule.title`)을 최대 2개 `·` 로 잇고 나머지는 `외 N`,
  전체 목록은 `title` 속성에 남긴다. 앞의 플라스크 아이콘이 '왜 뽑혔나' 라벨을 대신한다.
  슬러그(`f5_prog_persistent`)를 화면에 노출하지 않는다 — 부모가 `lib/api.getRuleTitleMap()`
  으로 매핑해 `ruleTitles` 로 내린다. `rule_names` 가 NULL 이면 '종합 점수 상위 선정'.

### `/reports/{date}` — 그 날짜의 추천 (색인 정본)
**홈과 일부러 다른 헤더**를 쓴다 — 이 화면의 축은 '추천'이 아니라 '그 날짜'다.
날짜 이동(`pick/DateStepper`, 버튼에 **이동할 날짜**를 적는다)과 그날 주도 섹터가 여기 있고,
최근 성적·매크로 경고·시장 요약은 홈에만 있다. 본문은 홈과 같은 `PickList` 를 공유한다.
가장 최근 거래일로 가는 링크는 `/` 로 보낸다 — 같은 내용의 URL 을 둘로 만들지 않는다.

### `/record` — 추천 성적
- `pick/RecordSummaryPanel` — 누적 승률·평균 갭·평균 실체결·최고/최악일.
  **최고일과 최악일을 같은 크기로** 낸다(좋은 수치만 크게 띄우지 않는다).
- ⚠️ 평균 실체결(`exec_leg_ret`)은 매매 경로 가동 이후 구간에만 있어 갭과 **창이 다르다**.
  `exec_days !== days` 면 실체결 자신의 구간(`exec_from_date~exec_to_date`)을 부제에 찍는다 —
  두 평균을 같은 창인 것처럼 나란히 놓으면 성적이 부풀려 읽힌다.
- 타일 아래 **본문 한 문장**(`lib/record.recordSentence`) — 집계 구간·모수·매매 전제를 문장으로
  말한다. 타일 숫자만으로는 "종가베팅 승률" 류 검색 질의에 답이 될 본문이 없다
  (근거: `docs/plan/seo/search-visibility.md`). 빌더는 **성적을 새로 계산하지 않고**
  `RecordSummary` 값만 끼우며, 메타 description(`recordMetaDescription`)도 같은 파일에 있다.
  - **한 문장이고 보이게 둔다.** 여러 문단을 쓰면 바로 위 타일과 중복이고, 접어서 감추면
    검색엔진 전용 텍스트가 된다. 최고·최악일과 실체결 구간은 타일이 이미 갖는다.
- **매매 전제(장 마감 매수 → 다음 날 아침 매도)는 이 문장 한 곳**에만 둔다. 헤더 설명·각주·본문이
  각자 같은 전제를 적으면 한 화면에 같은 문장이 세 번 나온다. 그 아래 각주는 면책만 담고,
  헤더 kicker 는 h1(`추천 성적`)과 다른 문구(`지난 추천 기록`)를 쓴다.
- 아래는 `ReportCalendarGrid` (날짜별 승패·대표 종목·테마·매크로·휴장). 셀 → `/reports/{date}`.
- 데이터: `/api/stock-report/record-summary?days=` · `gap-stats` · `top-picks` ·
  `sector-report/top-themes` · `market-holidays` · `macro-events`.

### `/reports/{date}/{ticker}` — 종목 상세
순서: 헤더(룰 칩) → **왜 뽑혔나** → **어떻게 매매하나** → 갭·실체결 결과 → 상세 데이터
(기본정보·수급·차트·콘텐츠·뉴스 재료·점수) → 면책.
- `pick/WhyPicked` — 수급/기술/재료 3축 한 줄 요약. **새로 판정하지 않고 저장된 값을 서술만** 한다.
- `pick/TradePlan` — 진입(리포트가) · 청산(익일 시가) · 손절(`FixedLossCalculator`).
  성적 집계의 전제를 화면에 밝혀, 다른 방식으로 매매해도 같은 성적이 날 거란 오해를 막는다.
- 실체결 손익률(`exec_leg_ret`)은 갭과 별개 줄로 낸다(참조가 기준 ≠ 체결가 기준).

### `/market` — 시장
**지수 / 섹터** 세그먼트로 나눈다(`?view=sector`, 기본 지수). 한 화면에 다 쌓으면 모바일에서
섹터까지 스크롤이 너무 길다. 탭은 늘리지 않고 화면 안에서만 가르므로 canonical 은 `/market` 하나다.
- 지수 뷰(기본) — `MarketClient`(지수·경제 일정, 실시간 폴링이라 클라)
- 섹터 뷰 — `market/SectorBoard`(섹터 랭킹 + 언급이 몰린 섹터 칩).
  섹터·언급 데이터는 이 뷰일 때만 페치한다(기본 뷰의 왕복을 줄인다).
- `loading.tsx` 의 헤더 문구는 `page.tsx` 와 **같아야** 한다(전환이 튀지 않게).

### `/news` — 뉴스 탭
**뉴스 / 콘텐츠** 세그먼트로 나눈다(`?view=content`, 기본 뉴스). 둘 다 '어떤 재료가 돌고 있나'
라는 같은 질문이지만 출처·시간축이 달라 한 화면에 쌓으면 스크롤만 길어졌다.

**뉴스 뷰** — 요약 타일 → 종목별 재료 → 헤드라인 스트림 3층 + 사이드 '뉴스가 몰린 종목' 랭킹.
**날짜를 이동**한다(`?date=YYYY-MM-DD`, 기본값은 **가장 최근 리포트일**).
- `news/MaterialBoard` — 단일 목록 + 필터(등급·선정·재료 유형 칩) / 정렬(평소보다 뉴스 많은
  순·등락률·후보 순위) / 검색. 기본 정렬은 평소보다 뉴스 많은 순(배수).
  행을 누르면 판정 근거가 있는 `/reports/{date}/{code}` 로.
- `news/NewsBuzzRail` — 후보 밖 종목까지 덮는 랭킹. 후보인 종목엔 '후보' 배지.

**뉴스량 라벨 (`lib/news.newsHeatLabel`)** — 홈 `NewsDigest` · `NewsBuzzRail` · `MaterialBoard`
세 화면이 **같은 문구**를 쓴다. 강조 한 줄(`뉴스 N배` · `첫 등장` · `평소 수준` · `뉴스 없음`)과
근거 한 줄(`뉴스 41건 · 평소 10.0건/일`)로 나오고, 강조가 아닌 값은 회색으로 눕힌다.
- 배수는 **정수 반올림**, 10배 이상은 `10배+`. 소수점 한 자리는 없는 정밀도다.
- **직전 7일 언급이 0건이면 배수를 쓰지 않고 `첫 등장`** 이다 — 백엔드 분모 하한이 1이라
  그 경우 배수가 곧 오늘 건수이고("3배"가 아니라 "처음 떴다"), 정렬이 배수순이라 이런 종목이
  상단에 몰린다. 배수 계산 자체는 정렬(백엔드 `surprise`)과 같은 식을 쓴다 — 갈리면 순위와
  라벨이 어긋난다.
- `news/NewsStream` — 헤드라인 스트림(40건씩 '더 보기'). 기사 단위로 접히고 시세 기사는 기본 숨김.
- **콘텐츠 뷰** — `news/MentionPulse`(언급 트리맵) + 콘텐츠 카드 목록(12건씩 페이지네이션,
  `?view=content&page=N`). 예전 `/feed` 탭의 본문을 그대로 옮긴 것이다.
- 지속성 라벨은 **candidate 표본(관찰 전용·미검증)** 이라는 안내를 접이식으로 두되, 핵심 문구는
  닫힌 상태에서도 보이게 남긴다.
- 데이터: `/api/news/materials` · `/api/news/heat?date=` · `/api/news/stream`(로컬 프록시 경유) ·
  `/api/contents` · `/api/contents/mention-stats` ·
  `/api/stock-report/dates`(날짜 이동은 영업일 목록 위를 걷는다).

### 재료·룰 표시 공통 규칙
- **뉴스 재료 섹션**(종목 상세) — 등급 칩 + 사실 4축 + **판정 근거 문장**(`news_label_reason`) +
  후속 재료 실현 일수. 등급만 보여주면 화면에서 오탐 감사가 안 되므로 근거 문장을 반드시 노출한다.
  근거 문장은 `lib/news.humanizeMaterialReason` 가 내부 항목명을 한글로 치환한다(조사 교정 포함) —
  ⚠️ **판정 항목을 추가하면 이 치환표에도 넣는다**(빠지면 영문 필드명이 화면에 샌다).
- `TodayNews` — 시세보도 기사는 `details/summary` 로 접는다(서버 컴포넌트 유지, CSS-only 토글).
- **룰 링크**는 종목 상세 헤더 칩에만 둔다(카드는 전체가 이미 `Link` 라 중첩 불가).
  칩은 한글 제목을 쓰고 슬러그는 링크 경로로만 남긴다.
- `components/MaterialBadge.tsx` — 연속/중립/소진/미판정 공통 칩 + `materialAxisLabels`(사실 축을
  사람 말로). `/news`·종목 상세가 공유한다.

### `/lab` — 전략 실험실 (읽기 전용 공개)
서버 컴포넌트가 `getEdgeRules()` + rule 별 일별 시계열(+최신 매칭 1일치)을 실어 `EdgeBoard`(클라)로 내린다.
- 상태 그룹: 실전 적용 → 검증 중 → **측정용 기준선** → 판정 종결(접힘) → 종료(접힘).
  + 요약 스트립(`EdgeSummaryStrip`) + 접이식 도움말.
- **검증 중은 회색조+진행바(모의), 실전 적용은 컬러** — "모의 성적 ≠ 실탄"을 시각으로 구분한다.
- **판정 종결**(`lib/edge.isDecided`)은 최하단 접힘 섹션으로 모으고, 카드에 판정 결과(판정 탈락·재현
  실패)와 사유를 찍는다. '검증 중'·'검증 통과' 집계에서 제외한다.
- **판정 단계 라벨**(`lib/edge.decisionLabel`)은 정책을 함께 본다: 발견 통과 후 `strict` 는
  '확인창 진행'(대기), `experimental` 은 승격에서 확인창이 면제되므로 **'발견 통과'(통과 색)**.
  정책은 서버가 준 `stats.promo_policy` 를 읽기만 한다(프론트 조건 재계산 금지).
- **측정용**(`lib/edge.isMeasurementOnly`, role=benchmark)은 검증→투입 파이프라인 밖이라 상태 배지·
  진행바·'검증 통과' 배지를 숨기고 별도 섹션·타일로 뺀다. 단 '종료'는 수명 정보라 표시한다.
- **종료 사유**(`lib/edge.retireReason`): '종료'는 이유가 여러 가지라(통계 탈락 / 성적 붕괴 /
  **적용 불가**) 기본 문구 "검증에 실패했거나 수명이 다해"가 틀릴 수 있다. `decision.retire_reason`
  이 있으면 상세 화면 상태 설명줄에 그 문장을 대신 쓰고, 카드에선 '종료' 배지 툴팁으로 붙인다
  (레이아웃 불변). 통계는 멀쩡한데 매수 시점에 평가할 방법이 없어 내린 rule 이 이 경우다.
- 카드 높이 통일: 검증 상태 슬롯(상태·진행바·설명 3줄)은 **항상** 렌더한다(설명 없으면 공백 한 줄).
- 카드를 누르면 `/lab/[name]` 상세(일별 막대차트·선정 조건·최근 매칭). 매칭 종목명은 **그 날짜의
  리포트 상세**로 링크하고, 반대 방향은 '룰 선정' 배지가 `/lab/[name]` 으로 되돌린다.
- 색인: `app/sitemap.ts` 가 **검증 거래일이 `PROMO_MIN_DAYS`(10일) 이상 쌓인 룰만** `/lab/[name]` 으로
  싣는다(그 아래는 성적표가 몇 줄뿐이라 색인 가치가 없다 — `/stocks/` 와 같은 기준).
  상세 description 은 **역할(매수/위험 회피/측정용)을 앞에 붙이고 성적을 룰 설명보다 먼저** 쓴다 —
  역할을 빼면 제외 규칙 성적이 매수 수익률처럼 읽히고, 성적을 뒤로 밀면 스니펫에서 잘린다.
- 컴포넌트: `EdgeSummaryStrip` · `EdgeRuleCard` · `EdgeRuleDetailContent`.

### `/admin/edge-rules` — 전략 관리 (admin)
실전 투입(promote)/종료(retire)는 **여기서만** 한다(공개 화면엔 버튼 없음).
섹션: 검증 통과 대기 → 실전 적용 중 → 검증 중 → **측정용 기준선**(종료만 가능 — 기준선 교체는 의도적
수동 작업) → 종료(접힘). 확인 다이얼로그 후 `app/api/edge-rules/[id]`(admin 프록시) 호출 —
조건 미충족 409 사유를 그대로 표시한다(**게이트는 백엔드 단일 소스**).
